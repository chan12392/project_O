# Linux 카드 격리 검토 (구현 전)

현재 Linux `KillOnClose::stop_and_confirm`은 직접 자식만 중지하고 항상 `false`를 반환한다. 따라서 자식이 정상 종료해도 예약을 유지한다. 직접 자식의 PID·종료 상태와 프로세스 그룹 종료만으로 그룹을 떠난 자손이 없다고 증명할 수 없으므로 이 동작을 해제 근거로 바꾸면 안 된다.

## 커널 격리와 권한

- Linux 5.7 이상의 [`clone3(CLONE_INTO_CGROUP)`](https://man7.org/linux/man-pages/man2/clone.2.html)은 cgroup v2 디렉터리 파일 디스크립터를 지정해 자식을 처음부터 그 그룹에 생성한다. 일반 프로세스를 실행한 뒤 옮기는 방식에는 그 사이 자손이 생길 수 있는 구간이 있다. 이 호출에도 커널의 cgroup 이동 권한 제약이 적용되며 시스템에 따라 커널·권한·격리 정책이 호출을 거부할 수 있다.
- [cgroup v2 문서](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html)에 따르면 `cgroup.events`의 `populated 0`은 해당 그룹과 하위 그룹에 살아 있는 프로세스가 없다는 뜻이고, `cgroup.kill`은 해당 트리의 프로세스를 종료하면서 동시 fork와 이동을 처리한다. **읽는 대상이 생성 당시의 격리 단위이고 자손이 이전에 이탈하지 못했다는 별도 증거가 있어야** 이것이 작업 전체의 종료 증거가 된다.
- 위임된 하위 트리는 목적지와 출발지의 공통 조상 `cgroup.procs`에 대한 쓰기 권한으로 이동을 제한한다. 작업자와 관리자가 같은 사용자라면 작업자가 같은 권한 또는 서비스 관리자 요청으로 다른 그룹에 프로세스를 배치할 수 있는지 실제 환경에서 검증해야 한다. 같은 사용자에 대한 보호 경계가 확인되지 않으면 `populated 0`만으로 해제하지 않는다. 별도 서비스·외부 시스템에 위임한 비동기 작업도 cgroup의 종료 증명 범위 밖이다.
- [systemd 임시 서비스](https://www.freedesktop.org/software/systemd/man/latest/systemd-run.html)와 [KillMode=control-group](https://www.freedesktop.org/software/systemd/man/latest/systemd.kill.html)은 후보지만, 사용자 관리자 접근과 이탈 가능성, 서비스 자동 수거·재시작, 표준 입출력·환경 전달 및 관리자 종료 후 복구를 확인하지 않았다. 단위 이름이 없거나 조회가 실패했다는 사실은 종료 증거가 아니다.

## 예약 상태 전이 제안

[SQLite의 원자 트랜잭션](https://www.sqlite.org/transactional.html)은 DB 변경에 적용된다. cgroup 생성·프로세스 생성은 DB 트랜잭션 밖의 커널 동작이므로 둘을 한 번에 커밋할 수 없고, 중간에 종료되어도 안전한 상태 기계가 필요하다. 기존 구현은 자원·슬롯·시작 횟수를 한 트랜잭션에서 예약하고, 실행 직전 `spawn_intent`를 기록하며, 복구는 즉시 쓰기 트랜잭션에서 소유자와 기록을 다시 확인한다.

1. 재사용되지 않는 실행 시도 식별자와 부팅·관리자 신원, 격리 단위의 검증 가능한 식별자를 예약에 기록한다. 부팅 후 경과 시간으로 표현되는 [`/proc/<pid>/stat`의 시작 시각](https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html)과 PID만으로 재부팅이나 네임스페이스 변경을 구분한다고 가정하지 않는다.
2. 시작 의도를 먼저 영속 기록한 후 검증된 격리 단위 안에서 시작한다. 시작 의도 기록 후 생성 전후에 실행기가 죽으면 실제 시작 여부는 불명으로 남긴다. 격리 생성이나 권한 검증 실패 시 작업을 시작하지 않는다.
3. 정상 종료·중지 시 격리 단위의 신원과 이탈 불가 조건을 확인하고 트리가 비었음을 관찰한다. 다른 프로세스가 다시 단위에 들어오거나 새로운 작업이 시작될 수 있는 경합을 막은 상태에서 종료 증거를 기록한 뒤에만 예약을 해제한다.
4. 소유자 사망 후에는 기록된 동일 격리 단위의 신원과 종료를 재확인하고 트랜잭션 안에서 예약을 다시 읽어 조건부로 복구한다. 단위 삭제·재생성, 관리자 재시작, 접근 거부, 확인 불가 및 기존 예약은 안전한 증거가 없으면 불명으로 남긴다. 파일 경로·PID·단위 이름만의 일치나 관찰한 빈 상태만으로 신원과 이탈 불가를 단정하지 않는다.

이 상태 기계와 식별 방식은 설계 후보이며 운영 코드에 구현하거나 안전성을 검증한 것이 아니다. 기존 저장소의 다른 미커밋 변경을 보존했다.

## 수행한 실험과 남은 검증

독립 테스트 `cargo test -p o-core --test resource_recovery_atomic`은 Windows에서 두 시작 표식 요청 중 하나만 성공하고 동시에 실행한 살아 있는 소유자의 복구 요청이 거부되며 독점 예약이 남는 것을 확인했다. Linux 대상으로 같은 테스트의 `cargo check`는 통과했지만 실행하지 않았다. WSL 배포판과 Docker/Podman이 없는 Windows 호스트에서 Zig와 `x86_64-unknown-linux-gnu` Rust 타깃으로 교차 검사했다.

실제 Linux에서 권한이 충분한 경우와 부족한 경우, `clone3` 실패 및 실행 직후 생성된 자손, `setsid`와 cgroup 이동 시도, 같은 사용자 관리자 요청, 정상 종료·중지·실행기 강제 종료, cgroup/관리자 재생성, 재부팅·PID 재사용, 여러 실행과 복구의 경쟁을 검증해야 한다. 이 검사는 별도 임시 프로젝트와 테스트 자원만 사용하고 Git worktree나 실제 구독을 만들지 않아야 한다.
