project_O 아키텍처

총괄 에이전트가 일을 작업카드로 나누고, O CLI가 공식 에이전트 CLI들에 병렬로 맡기고, 앱은 그 기록만 읽어 채팅·사무실·대시보드로 보여 준다.

사람

대표님

프로젝트 총괄에게 무엇을 할지만 자연어로 요청한다.

  • "todo 앱에 다크 모드 넣어줘"
  • 어느 에이전트·모델로 할지는 총괄이 정한다
  • 직접 지정하면 그대로 따른다
→
프로젝트마다 하나

총괄 (Claude Code + O 스킬)

요청을 서로 겹치지 않는 작업카드로 나눠 계획(JSON)을 만든다.

  • 카드마다 에이전트·모델·노력 수준을 일에 맞게 고른다 (한도는 o usage로 확인)
  • 유휴 시 쉬고, 부르면 최근 세션을 불러온다
  • 팀 대화로 카드에 답한다: o msg send
  • 끝나면 카드별 결과를 정리해 보고
→
중간 라우팅

O CLI

  • o dispatch 정책 검사 후 백그라운드 병렬 실행
  • 정책: 카드 8장·동시 6개·프로바이더별 상한·하루 60건, 한도 걸린 서비스 재사용 차단, 실행 파일·인자·계정 지정 금지
  • o msg 카드 사이 팀 대화 (정책 검사)
  • o usage 구독 한도를 각 CLI에 물어 저장
  • o status · o events · o stop

브랜치 흐름

개인·작업 브랜치→ test_2 (자유 통합, 읽기 전용 거울)→test_1→main

test_2는 누구나 병합, test_1은 다른 팀원 1명이 승인한 뒤 누구나(대표는 바로) 병합, test_1_hotfix·main_hotfix·main은 대표(A)만 병합한다. 병합은 merge commit만.
