# 카드 작업 폴더의 공용 빌드 캐시와 빌드 산출물 정리

2026-11-18, [브랜치 정리와 빌드 산출물 절감 조사](2026-11-13-branch-cleanup-and-build-footprint.md)가 남긴 “워크트리마다 GB 단위 `target`” 문제를 구현으로 옮겼다. 사람이 고른 방향은 공용 `CARGO_TARGET_DIR`과 실행 종료 뒤 빌드 산출물 정리다.

## 무엇이 바뀌었나

| 지점 | 동작 |
|---|---|
| 카드 시작 (`run/runner/card.rs`) | 카드가 분리 작업 폴더(`<상태 폴더>-worktrees/<실행 ID>/<번호>`)에서 시작하면 `CARGO_TARGET_DIR`을 `<상태 폴더>-cache/cargo-target`으로 준다. 분리 폴더 하나에 `target`이 쌓이지 않고, 여러 폴더와 실행이 같은 캐시를 함께 쓴다. 이때 트랜스크립트에 `O 빌드 캐시 <경로>` 줄을 남긴다 |
| 실행 종료 (`run/runner.rs`, `run/workspaces.rs`) | 실행이 끝나면 그 실행이 만든 Git 워크트리마다 `target`·`node_modules`를 지운다(체크아웃 루트에서 세 단계 아래까지, `app/node_modules` 포함). 편집한 파일과 Git 상태는 그대로 두어 검토(`review_changes`)와 복구가 이어진다. 결과는 `<실행 폴더>/build-cache.json`에 지운 것·남긴 것·실패로 나눠 기록한다 |
| 후속 작업 | 후속 실행의 작업 폴더도 같은 캐시를 쓰고, 그 후속 실행이 끝나면 같은 정리 대상이 된다 |

## 지키는 경계

- **원본 프로젝트는 건드리지 않는다.** 정리는 `<상태 폴더>-worktrees/<실행 ID>/<번호>` 모양과, 그 폴더의 `.git`이 폴더가 아니라 파일이라는 것(Git이 만든 연결 워크트리), `git rev-parse --show-toplevel`이 그 폴더라는 것을 모두 확인한 폴더에만 한다. 원본 프로젝트와 Git이 없는 복사본(`git init`, `.git`이 폴더)은 거부한다. 복사본의 `target`은 프로젝트에서 복사된 것일 수 있어 지우지 않는다.
- **Git이 추적하는 폴더는 지우지 않는다.** `target`이라는 이름의 소스 폴더가 추적 중이면 그대로 둔다.
- **링크를 따라가지 않는다.** 캐시 폴더 자리에 링크·연결 지점이 있으면 그 너머에 쓰지 않고 거부한다. 정리 중에도 링크 디렉터리는 지우지 않는다.
- **아직 쓰는 폴더는 그대로 둔다.** 그 카드가 아직 실행 중이거나(활성 표식), 그 카드의 후속 실행이 접수되어 아직 끝나지 않았으면 정리하지 않고 `build-cache.json`의 `kept`에 이유를 남긴다.
- **사람이 정한 `CARGO_TARGET_DIR`이 이긴다.** O를 띄운 환경에 이미 값이 있으면 덮어쓰지 않는다.
- **샌드박스가 있는 CLI는 자기 출력을 그대로 쓴다.** Codex 카드(비 YOLO)는 `-s workspace-write`로 돌아 작업 폴더 밖에 쓸 수 없다. 공용 캐시를 주면 카드의 빌드 명령이 실패하므로 주지 않고, 그 카드의 `target`은 실행이 끝날 때 위 정리로 회수한다. Codex 카드에도 공용 캐시를 쓰게 하려면 `--add-dir`로 캐시를 쓰기 허용 폴더에 더해야 하며, 이는 카드가 쓸 수 있는 범위를 넓히는 결정(ADR-0043의 우편함 경계와 나란히)이라 지금은 하지 않았다.

## 정책·가드와의 관계

- `policy.rs`의 `o_siblings`에 `<상태 폴더>-cache`를 더했다. 계획의 `project`가 그 폴더이거나 그 안이면 다른 O 폴더처럼 거부한다. 카드가 공용 캐시를 자기 프로젝트로 삼아 복사·격리하는 일을 막는다.
- 공용 캐시는 O 상태 폴더 밖(`<상태 폴더>`의 형제)이라 상태 폴더 보호 규칙(도구로 바꿀 수 없음)에 걸리지 않는다. 카드의 빌드가 그곳에 쓰는 것은 의도된 동작이다.
- `events.jsonl` 형식은 바꾸지 않았다. 카드 시작 전에 남기는 `card.tool`(`O 빌드 캐시`)은 기존 화면이 그대로 읽는다.

## 검증

- `crates/o-core/src/run/workspaces.rs` 단위 검사: 공용 캐시 위치, 워크트리의 미추적 `target`·`node_modules`·`app/node_modules`만 삭제, 추적 중인 `target` 보존, 원본 프로젝트와 비 Git 복사본 거부, 캐시 자리 링크 거부.
- `crates/o-core/tests/runner.rs` 통합 검사: 두 카드가 같은 캐시를 받고 실행 뒤 각 워크트리에서 산출물이 사라지며 원본 프로젝트의 산출물은 남는지, `review_changes`가 계속 동작하는지, 후속 작업이 대기 중이면 그 폴더를 남기는지, 샌드박스 Codex 카드는 공용 캐시를 받지 않는지.
- `crates/o-core/tests/policy.rs`: `<상태 폴더>-cache/cargo-target`을 프로젝트로 쓰는 계획 거부.

## 남은 것

- 공용 캐시 자체는 지우지 않는다(다시 쓰라고 만든 캐시다). 필요하면 사람이 `cargo clean`이나 폴더 삭제로 정리한다.
- Codex 카드의 공용 캐시 사용은 위 경계 때문에 넣지 않았다.
- Claude 카드가 사람 설정의 샌드박스를 켜 두면 작업 폴더 밖 쓰기가 막혀 공용 캐시를 쓰지 못할 수 있다. 그때는 카드가 빌드 오류를 보고하고, 실행 종료 정리가 자기 `target`을 회수한다.
- 여러 카드가 같은 캐시에 동시에 빌드하면 Cargo의 캐시 잠금으로 서로 기다린다. 병렬 카드가 같은 순간에 빌드할 때의 지연은 측정하지 않았다.
