# 보안 후속 조치와 워크트리 정리

기준은 앞선 구현·검증을 올린 `565e870`이다. 이 보고서는 남은 보안 수정, 추가 검증, 실제 워크트리 정리를 구분한다. 원래 사용량·모델·구독 전환·분배 작업은 [앞선 통합 보고서](2026-11-12-implementation-and-validation.md)를 따른다.

## 통합한 변경

- `6679e51` / 통합 `5593dc9`: 사람이 본 계획과 실제 실행 입력을 연결했다. 계획 전체·모델·effort·프로필·권한 모드·후속 참조를 부모가 보관하고 OS가 상대를 확인한 파이프로 전달한다. 저장 파일을 바꿔 실행 내용을 바꾸는 경로를 제거했다. [상세 검증](2026-11-12-execution-integrity.md), [ADR-0049](../decisions/0049-approved-execution-input.md).
- `b852f24` / 통합 `a7ce853`: 현재 GTK 경로와 호환되는 glib 0.18.5에 공식 수정 두 줄을 적용했다. 버전을 꾸미거나 경보를 무시하지 않고 소스 해시와 Cargo 해석을 검증한다. 잠금 의존성 점검을 필수 CI와 주간 workflow에 연결했다. [상세 검증](2026-11-12-dependency-security.md), [ADR-0050](../decisions/0050-glib-backport-and-dependency-checks.md).
- Windows 에이전트의 상태 접근 격리는 로컬 `younchan-state-isolation`의 시제품 `f72254d`, 후속 수정 `164e0aa`, 대안 API 진단 `55a64d5`로 보존했다. 후속 수정은 ACL 회수 순서·오류 보고, 로그온 세션 간 잠금, 브로커 종료·대기 취소, 부모가 신뢰한 Git 폴더의 자식 한정 설정을 다룬다. 공식 CLI 호환 실패가 남아 `younchan`에 코드를 통합하지 않았으며 이 부분을 해결로 세지 않는다.

원본 감사 50개 항목 중 현재 조치표는 `fixed 28 / refuted 6 / documented-limit 12 / deferred 4`다. 보류 4개는 승인 결정·상태 파일·터미널·원시 로그의 OS 접근 경계이며, 현재 구현 중인 항목과 문서화된 신뢰 한계를 혼동하지 않는다.

## 검증

- 실행 입력 담당 검증: 실제 Windows 부모·자식 파이프와 변조된 저장 파일, 다른 부모의 입력 거부, CLI/총괄/후속 실행, TypeScript 전체 263개 및 영향 검사 통과. 실제 공급자 대신 가짜 CLI를 사용했다.
- 공급망 담당 검증: 모든 플랫폼의 잠금 버전 464개 실제 조회, npm 취약점 0개, 감사 검사기 회귀 10개, Windows 전체 컴파일·라이선스·정책 검사 통과. 유지보수 중단 경고 4건은 별도로 남는다.
- 통합 작업 폴더에서 앱 화면 빌드가 통과했다. 동적 import 경고는 남아 있으며 빌드 실패는 아니다.
- Windows 격리의 모의 자식·손자 프로세스는 상태 읽기/쓰기·DACL/소유자 변경·부모 핸들 접근 거부와 자기 작업 폴더 쓰기를 확인했다. 후속 수정 뒤 총괄 54개·카드 43개, 터미널 8개, 승인 15개, ACL 회수·메시지 취소 각 1개, 실제 AppContainer 시험과 clippy·정책 검사 633개 파일이 통과했다. 실제 격리 PTY에서 승인 허용·거절과 대기 중 브로커 종료를 확인했다. 다른 로그온 세션의 실제 운용과 영구 ACL 복구는 미검증이다.
- 실제 Git의 합성 detached 작업 트리에서 `status --porcelain`을 확인했다. 부모의 같은 환경에서 신뢰한 폴더 하나에만 자식 환경 설정을 추가하며 전역 예외는 쓰지 않는다. 확인 실패 시 예외를 생략하고, 잘못된 `GIT_DIR`을 자식 Git도 종료 코드 128로 거부했다. 커밋·push 등 전체 Git 쓰기 경로는 미검증이다.
- 시제품의 기존 생성 경로에서는 공식 Codex의 모델 없는 명령 시험이 `no home dir`, Node의 실제 패키지 실행이 드라이브 루트 `lstat` 권한 문제로 실패했다. 같은 합성 환경의 일반 자식은 성공했으나 LPAC와 표준 AppContainer 모두 실제 사용자 홈 조회·메타데이터 접근이 거부됐다(`FOLDERID_Profile` 기본 플래그: `0x80070005`, `DONT_VERIFY`: 성공, 반환 경로의 메타데이터 조회: 오류 5). 루트·홈의 기존 Win32 격리 capability를 현재 생성 경로에 추가한 시험도 프로세스 생성 오류 87로 실패해 추가 코드는 되돌렸다.
- 새 Windows sandbox API 비교에서는 실제 AppContainer 토큰과 보호 fixture 읽기·쓰기 거부를 확인하고 홈 조회를 통과했다. Codex 0.167.2는 공개 실행 파일과 기존 스텁의 읽기 권한만으로 버전 조회까지 성공했지만 모델 없는 실행은 `CreateDesktopW failed: 5`로 실패했다. Node 22.23.2의 symlink 보존 옵션도 시작만 가능하고 실제 루트·경로 조회는 실패했다. 루트 읽기 허용은 보호 fixture 읽기까지 열었으며, 루트 쓰기 허용은 루트 속성 변경용 핸들을 허용해 어느 것도 제품 설정으로 채택하지 않았다. 일반 제한 토큰 비교도 프로세스 초기화에서 실패했다. 기존 사용자 프로필·홈·시스템 루트·윈도 스테이션 ACL과 설치 CLI는 바꾸지 않았다. 최종 진단 시험 1개와 해당 clippy가 통과했고 정책 검사 633개도 통과했다. 상세 결과와 원본 로그 경로는 시제품의 `docs/reports/2026-11-13-state-isolation-followup.md`에 있다. 공식 CLI·다른 프로바이더·총괄 계획 제출 경로의 호환성은 남아 있다.
- Linux GLib 실제 실행, 설치 앱 교체·실제 Tauri 자식 기동, 새 격리를 적용한 실제 Codex 모델 호출, Claude 구독 한도 전환은 아직 확인하지 않았다. 주간 점검은 기본 브랜치 반영 후에 활성화된다.

## 워크트리 정리

처음 등록된 것은 본체를 포함해 26개였다. 종료된 깨끗한 워크트리 14개를 독립 Git 저장소·전체 이력 bundle·변경 목록·파일 검증 기록과 함께 `%USERPROFILE%/Desktop/delete/project_O-20261112-222756-48110360`으로 옮겼다. 각 이동 직후 Git 연결·HEAD·status와 전후 파일 목록을 대조했고 원본 저장소 등록에서도 분리했다. 원본 파일을 영구 삭제하는 명령은 실행하지 않았다.

이후 별도 읽기 전용 대조 도중 아카이브가 사라졌고 **대표님이 직접 삭제했다고 확인했다.** 따라서 이 14개 정리는 대표님 삭제로 종결됐다. 현재 그 경로에 복구용 보관본이 있다고 안내하지 않는다. 이동 시 확인과 별도로 계획했던 독립 해시 재대조는 완료하지 못했다.

남은 원본 등록은 본체 포함 12개다.

- 기존 변경 워크트리 7개: 최초 inventory와 Git status 54개 항목이 일치하며 그대로 보존했다.
- 종료된 워크트리 1개: 이동 때 파일 사용 중 오류가 나서 원본과 등록을 유지했다.
- 작업자 폴더 3개: 코드 통합·검증에 사용했다. 완료된 실행 입력·공급망 작업 브랜치는 병합 후 삭제했고, 해당 폴더는 커밋을 가리키는 detached 상태로 남아 있다.
- 본체 `younchan`: 사용자의 원본 감사 문서 6개를 보존했다. 정책 위반 재현 문자열이 있는 원문은 커밋 대상에 포함하지 않는다.

남은 변경 폴더와 작업자 폴더의 캐시는 다른 정리 세션에서 16개 대상 이동이 권한 오류로 차단된 범위와 겹친다. 이 차단을 부모 폴더 이동·ACL 변경 등으로 우회하지 않았다. 저장소 외부 워크트리 숨김과 실제 파일 정리는 별개이며, 숨김만으로 원본 12개가 제거됐다고 하지 않는다.

## 본체 용량 원인

2026-11-13 파일 길이 합계는 **26,365,680,007바이트(24.555GiB), 86,957개 파일**이다. 디렉터리 링크를 따라가지 않았으며 읽기 오류는 없었다. 이는 논리적 파일 크기이며 실제 디스크 할당량과는 다를 수 있다.

## 문서와 코드의 차이

- 최초 감사 조치표와 SECURITY의 실행 계획·모드 변조 미해결 설명은 ADR-0049 구현보다 이전 상태였다. 실행 입력 경로는 새 코드를 기준으로 조치표를 갱신한다.
- 그래프의 `default_home` 설명과 달리 `crates/o-core/src/run/store.rs`는 `LOCALAPPDATA`를 사용하고, 없을 때 사용자 홈으로 돌아간다. 검사 환경의 상태 분리는 이 실제 구현을 기준으로 판단했다. 새 운영 설정 옵션은 추가하지 않았다.
- 독립 보존 대조 보고서의 최초 '위치 미상' 판단은 대표님의 직접 삭제 확인으로 해소됐다. 현재 경로가 존재한다는 전제로 복구나 추가 정리를 진행하지 않는다.
