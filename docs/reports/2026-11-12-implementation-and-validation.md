# 2026-11-12 통합 구현·검증 결과

대상은 `younchan` 소스와 대표 PC의 기존 실행 기록이다. 설치된 앱 교체나 배포는 하지 않았다. 별도 Codex 세션에서 기존 작업 복구, 보안 감사, 사용량·모델·전환을 각각 담당하고 총괄 체크아웃에서 병합·검증했다.

## 사용량과 모델 조사

앞서 설치 실행파일에서 공식 샌드박스 점검과 Codex 카드 시험을 마쳤다. 시험 실행 `20261112-070527-vock`의 앱 표시 합계는 128,622였지만 하위 세션 64,369가 빠져 있었다. 원본 기록 합계는 **192,991**이다. 신규 입력 51,825, 캐시 입력 140,928, 출력 238이며 비용 금액이 아니라 캐시를 포함한 토큰 수다. 상세 증거는 [Codex 실제 시험](2026-11-12-codex-smoke.md)에 있다.

명시한 모델과 effort는 실제 CLI에 전달됐다. 문제는 기본값을 사용하는 계획, 낡은 모델 표시, 하위 세션과 재개 사용량의 집계 경계였다. 이번 구현은 다음을 반영한다.

- Claude 전체 모델 합계·실패 응답·캐시 쓰기, Codex 하위 세션·상속 누적값·재개 기준값을 정산한다.
- 사용량 ID와 revision으로 정산을 교체하며, Rust·TypeScript·DB·토큰 보고가 같은 정산 계약을 쓴다. 전환 전후 프로바이더의 사용량을 따로 보존한다.
- 누락된 기준값이나 전체 자손 확인 불가 등은 불완전 집계로 표시한다. Codex 기록에서 찾은 모든 자손을 합쳐도 완전성을 증명할 수 없으면 완전하다고 표시하지 않는다.
- 모델 목록을 실제 프로필·프로젝트·CLI 기준으로 조회하고 캐시 수명, 조회 실패, 미확인 버전, 지원 effort를 전달한다. 총괄의 신규 계획에는 모델과 effort를 명시하도록 한다. 기존 수동 계획의 CLI 기본값은 유지한다.
- Fable 등의 버전을 고정한 표시를 제거했다. 공식 초기화 메타데이터의 Fable 5.2 표시는 fixture로 검증했으나, 이 PC 계정에서 실제 반환되는 최신 목록의 추가 조회는 훅 차단으로 검증하지 못했다.
- 과거 기록 보정은 명시적 미리보기가 기본이며 적용은 사람 전용이다. 실제 과거 기록에 보정을 적용하지 않았다.

## 구독 한도 자동 전환

기본 OFF이며 사용자가 대상 에이전트와 모델을 지정한다. 확인된 구독 한도에서만 다른 서비스로 한 번 전환한다. 일반 429, 인증·프로필 오류, 예산·권한 차단에는 전환하지 않는다. 같은 서비스의 계정을 돌려 쓰지 않는다.

CLI 전달, 총괄 계획 검사, 백그라운드 실행은 공통 사전검사에서 원래 한도 정보를 유지하면서 대체 대상까지 검증한다. 원래 승인 계획을 보존하고 실제 전환 대상을 이벤트에 남긴다. 시작 직전 설정을 다시 확인하며, 작업이 이미 진행됐다면 부작용과 인계 가능성을 확인한다. 불명확한 외부 작업은 자동으로 반복하지 않는다. 격리된 카드도 원래 프로젝트로 정책을 검사하고 기존 작업 폴더를 이어 쓴다.

Claude의 제한 이벤트 뒤에 구독 한도 문구가 도착하는 경우도 확인된 한도로 처리하되, 앞선 이벤트의 정확한 해제 시각을 유지하도록 통합 단계에서 보완했다.

## 기존 작업과 브랜치 표시

원래 실행 `20261112-052641-44g3`의 카드 1–7 작업을 복구했다. 예약 실행 표시, 하루 카드 수 60개 제한 제거, 실제 서비스별 구독 사용량·해제 시각, 사이드바 정렬·그룹·실행 표시 개수와 열린 이슈 #121, #86, #118, #84, #101의 수정을 포함한다. 동시 실행·계획 크기·사용 예산 제한은 유지한다.

실행에 브랜치 정보를 기록하고 사이드바에서 브랜치별로 묶는다. 개인 브랜치에서 시작하면 이름이 있는 작업 브랜치 하나를 만들며, 이미 작업 브랜치 안이면 추가 브랜치를 만들지 않고 카드별 워크트리로 격리한다. 원본 체크아웃의 HEAD와 파일은 유지한다. 옛 실행의 브랜치는 추측하지 않고 미기록으로 표시한다.

Orca는 발견된 외부 워크트리를 숨기도록 설정했다. 기존 작업 파일·원본 카드 폴더는 보존한다. 등록된 보안 작업 공간은 완료 상태로 바꾸고 주 작업 공간 아래로 정리했다. 병합된 임시 작업 브랜치는 깨끗한 체크아웃을 분리한 뒤 참조만 삭제한다.

## 보안 감사

6개 원본 보고서의 50건을 [조치표](../../security-audit/remediation.md)에 대응시켰다. **25건 수정, 6건 현재 코드에서 반증, 12건 신뢰 경계의 한계 명시, 7건 미해결**이다. 훅·명령 해석, 실행 설정, 승인 요청 결합, 링크된 상태 파일, 거울 Git, Tauri·개발 서버, CI 경계를 보완했다.

미해결 7건은 원시 로그의 민감정보와 보관 정책, 동일 사용자에 의한 승인 파일 위조, 상태·이벤트·DB 위조, 실행 모드 바꿔치기, 터미널 파일 IPC 위조, 승인 후 계획 바꿔치기, 정기 의존성 취약점 감시다. 동일 사용자 파일에 해시를 더하는 정도로 해결했다고 주장하지 않는다. 상태 소유권 분리와 인증 IPC, 불변 실행 입력 등의 후속 구조 변경이 필요하다.

## 건너뛴 동작과 검증 한계

- 원본 보안 보고서의 우회 예제가 커밋 정책에 걸렸다. 원문 6개는 사용자 파일로 보존하고 커밋에서 제외했다. 조치표와 수정 코드는 커밋한다.
- 워크트리 삭제 관련 명령 조회가 삭제 훅에 차단됐다. 재시도하지 않고 표시·메타데이터만 정리했다.
- 새 정산기로 실제 시험 기록을 미리보기하고 Claude/Codex 메타데이터를 추가 조회하려던 명령은 실행 전 훅의 명령 형식 검사에 차단됐다. 재시도·우회하지 않았으며 실행됐다고 보고하지 않는다. 기존 실제 시험과 fixture·CLI 회귀 검사 범위를 구분한다.
- 실제 Claude 구독 전환, Linux 실행, 새 코드가 들어간 설치 앱의 네이티브 UI, 설치·배포는 검증하지 않았다. 기존 포맷 차이의 일괄 정리는 하지 않았다.
- 사용량 작업의 데모 개발 서버가 기존 감시 프로세스를 시작한 사실을 확인해 서버·감시 프로세스를 종료했다. 해당 시각 이후 실제 상태의 새 총괄·작업 질문·세션·사용량 이벤트 0건을 확인했다. 후속 데모 검사에서는 정적 preview 경로를 사용하도록 기록했다.
