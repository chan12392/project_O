# 프로젝트 스킬 선택

작업 폴더의 `.oskills/index.json`에 사용할 스킬을 등록한다. 목록은 로컬에서 검색하며, 작업 내용에 트리거가 포함된 스킬을 최대 5개 고른다. 영문·숫자 트리거는 단어 단위로 맞춘다(`UI`는 "Fix the UI"·"UI를"에 맞고 "build"에는 맞지 않는다. 복수형 등 다른 꼴은 트리거로 따로 적는다). 한글 트리거는 조사가 붙어도 맞도록 단어 안에서도 찾는다. 작업에 `$skill-name`을 직접 쓰면 해당 스킬을 우선하고, 직접 지정한 스킬은 다섯 개가 넘어도 빠뜨리지 않는다.

```json
[
  { "name": "game-logic", "path": "game-logic/SKILL.md", "triggers": ["게임", "game"] },
  { "name": "ui", "path": "ui/SKILL.md", "triggers": ["화면", "UI"] }
]
```

경로는 `.oskills` 폴더 안의 `SKILL.md`여야 한다. 폴더 바깥으로 이어지는 링크와 잘못된 목록은 사용하지 않는다. O는 선택한 이름과 파일 경로를 전달하고 내용은 직접 읽지 않는다. 에이전트의 기본 지침과 안전 규칙은 스킬보다 우선한다. 스킬 목록이 없거나 맞는 트리거가 없으면 스킬을 추가하지 않는다.

스킬 파일과 인덱스는 프로젝트가 제공하는 자료이므로 신뢰할 수 있는 내용만 등록한다. 이 방식은 아직 통합 스킬 관리 화면이나 기존 CLI의 내장 스킬 목록 제거를 제공하지 않는다.

## O 하네스 블록

O 상태 폴더(`%LOCALAPPDATA%/project_O/harness`)의 `index.json`에는 같은 형식으로 로컬 지침 블록을 등록한다. `path`는 이 폴더 안의 `.md` 파일이다. 작업의 트리거에 맞는 블록을 최대 5개 고르고 각 블록의 내용은 4KB 이하의 UTF-8이어야 한다. 쓸 수 없는 블록(4KB 초과, UTF-8 아님)은 건너뛰고 다음으로 맞는 블록이 그 자리를 채운다.

카드 프롬프트에 스킬이나 하네스 블록이 들어가면 실행 기록에 `card.guides { cardId, skills, harness }` 이벤트(이름만, 내용은 남기지 않음)를 남기고, 화면의 카드 기록에 "넣은 지침: 하네스 … · 스킬 …"으로 보인다. 예전 빌드는 모르는 이벤트 줄로 건너뛴다. 에이전트 CLI 자체의 기본 지침과 안전 경계는 유지되며 선택된 블록보다 우선한다. 목록과 블록은 신뢰할 수 있는 사용자가 관리한다.
