# ADR-0028: 총괄·카드의 질문을 사람이 고르게 한다

- 상태: 적용
- 날짜: 2026-11-04
- 관련: ADR-0008, ADR-0022, ADR-0023

대표 요청: 총괄이 "먼저 확인할 것"을 글로 늘어놓으면 사람이 따로 적어 답해야 했다. 질문은 팝업에서 고르고, 다 고르기 전에는 총괄의 답이 나오지 않으며, 카드(다른 에이전트)의 질문도 같은 곳으로 모으고, 창이 최소화·트레이에 있으면 알린다.

## 결정

- 총괄은 사람이 골라야 답이 정해지는 질문이 있으면 답·계획 대신 ` ```o-ask ` 블록 하나만 보내고 턴을 끝낸다(`lead::prompt::ASK_NOTE`, 매 턴 전달). 형식은 `{"questions":[{"header","question","options":[{"label","description"}],"multi"}]}`, 질문 1–4개, 보기 2–6개, 글자 수 상한이 있다(`split_ask`).
- O는 블록을 `lead.ask`(askId `<threadId>-q<n>`, provider, 블록 앞 글 `intro`, questions)로 저장하고 그 턴의 `lead.reply`를 남기지 않는다. 같은 답의 `o-plan`·`o-design`·`o-followup`은 받지 않는다(사람이 아직 고르지 않음). 형식이 틀리면 글은 `lead.reply`로, 사유는 `lead.error`로 남긴다. 새 세션의 지난 대화 요약에는 질문을 한 줄로 넣는다. 예약 실행에서 질문이 오면 사람에게 답을 요청하는 오류로 끝낸다.
- 앱은 답하지 않은 질문(그 뒤에 `lead.user`가 없음)을 모달로 묻는다. 모든 질문에 보기나 "기타" 글이 있어야 보낼 수 있고, 답은 그 스레드의 다음 메시지(`[질문 답변]` 목록)로 질문한 에이전트에게 보낸다. 실행 이벤트와 `SendRequest`는 바뀌지 않는다.
- 카드는 `o msg send --to lead "질문? [보기: A | B]"`로 묻는다(카드 프롬프트 한 줄, `CHOICES_OPEN`). 앱은 진행 중인 O 실행에서 일하는 카드가 lead에게 보낸 질문(물음 표현이나 보기)이 lead의 답보다 나중이면 같은 모달로 묻고, 답은 Tauri `run_reply`·개발 서버 `/api/lead/reply`가 `o msg send --as lead --to <카드>`와 같은 경로(`team::send`, 메시지 정책 검사)로 보낸다. Claude Code 세션의 하위 에이전트는 O가 답을 전달할 수 없어 묻지 않는다.
- 새 질문이 오면 창이 앞에 없을 때 데스크톱 알림을 띄우고 작업 표시줄 단추를 깜빡인다(`attention`, 트레이에 숨은 창은 알림만). 설정 → 알림 → "질문 알림"(기본 켬)으로 끈다. 알림 권한이 정해지지 않았으면 첫 질문 때 묻는다.

## 남은 것

- 총괄의 질문은 지금 보고 있는 프로젝트의 것만 묻는다(다른 프로젝트의 스레드는 읽지 않음). 창이 숨어 있으면 스레드 확인이 멈추므로, 앱에서 보낸 턴이 끝날 때 바로 확인한 결과로 알린다.
- Codex app-server의 턴 중 사용자 질문 요청(ADR-0023)은 여전히 빈 답으로 거절한다.
