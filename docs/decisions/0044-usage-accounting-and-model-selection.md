# ADR-0044: 하위 에이전트 사용량 집계와 실행 모델 선택

- 상태: 채택 — 분리 작업 브랜치에서 구현·회귀 검사. 실제 계정의 과거 기록 보정·설정 변경·설치·배포는 하지 않았다.
- 날짜: 2026-11-12
- 관련: [ADR-0004](0004-daily-usage-budget.md), [ADR-0008](0008-lead-chat.md), [ADR-0017](0017-agent-spec.md), [ADR-0022](0022-agent-session-continuations.md), [ADR-0023](0023-codex-app-server-and-terminal.md), [ADR-0035](0035-api-key-env-pass-through.md), [ADR-0037](0037-parallel-cards-and-subagents.md)

## 배경과 완료 기준

설치된 Project O의 실행 `20261112-052641-44g3`과 연결된 총괄 대화에서 확인한 문제를 고친다.

| 확인한 사실 | 근거 | 고친 뒤의 결과 |
|---|---|---|
| Claude 하위 3개에서 1,073,338토큰 누락 | 카드 result의 `usage`와 `modelUsage`, 하위 메시지의 입력·캐시 사용량 대조 | 전체 작업 트리를 포함하고 재개 세션을 중복 합산하지 않는다. |
| Codex 하위 8개에서 6,778,471토큰 누락 | 부모 ID가 연결된 12개 세션 기록의 요청별 합계와 최종 누적값 대조 | 부모에 속한 모든 깊이의 하위 세션을 한 번씩 포함한다. |
| Claude 메뉴는 Fable 5.1, 실제 카드는 Fable 5.2 | 고정 `LEAD_MODELS`와 실행 초기화·모델 사용량 기록 | 실제 실행 환경에서 조회한 목록을 표시한다. |
| 계획 8개 모두 `model` 생략 | 총괄이 생성한 원본과 저장 계획이 동일 | 새 계획에서 모델 선택을 명시하고 실제 실행 모델을 확인할 수 있다. |

이 기록의 프로젝트 합계는 20,239,032에서 **28,090,841토큰**으로 보정되어야 한다. 하위 사용량 7,851,809토큰이 추가되며, 같은 자료를 여러 번 읽거나 앱을 다시 시작해도 결과가 같아야 한다. 마지막 검토 카드는 시작하지 않았으므로 사용량을 만들지 않는다.

이번 실행의 총괄은 Opus 5.5, Claude 카드 3개는 Fable 5.2, Codex 카드 4개는 GPT-6.1-Sol이었다. 총괄의 모델 설정은 작업 카드에 상속되지 않는다. 이 사실을 모든 계정의 기본 모델에 일반화하지 않는다.

## 선택지

1. Fable 표시를 5.2로 바꾸고 Claude `modelUsage`를 그대로 더한다. 다시 낡아지는 목록, Codex 누락, 재개 세션 중복이 남으므로 선택하지 않는다.
2. 화면에서 원시 로그를 읽어 보정한다. CLI·개발 서버·총괄·프로젝트 합계가 서로 달라지므로 선택하지 않는다.
3. 기존 o-core의 프로바이더·사용량 집계·계획 경로를 확장한다. **이 방안을 채택한다.** 실행 방식과 인증·권한 경계는 유지한다.

## 결정 1: 사용량을 보고 범위에 맞게 정규화한다

### 집계 단위와 중복 방지

- 기존 `input`(캐시 쓰기 포함 신규 입력), `cached`(캐시 읽기), `output` 의미를 유지한다. reasoning 토큰처럼 output에 포함된 항목은 다시 더하지 않는다.
- 내부 보고는 provider, 실행 프로필, session ID, 보고 ID, 누적/증분 여부, 부모만/전체 트리 여부, 사용량, 확인 상태를 갖는다. 프로바이더별 의미를 파서에서 구분하며 숫자가 크거나 작다는 이유만으로 보고 범위를 추측하지 않는다.
- 누적값의 기준은 provider·프로필·session ID로 분리한다. 세션이 재개되어도 기준을 유지한다. 기준을 잃었거나 누적값이 감소해 초기화 여부를 확정할 수 없으면, 기존 원본으로 복원하거나 불완전으로 남긴다. 이전 값 전체를 이번 사용량으로 자동 합산하지 않는다.
- 한 번의 카드 실행 시도 또는 총괄 턴에 안정적인 `usageId`를 부여한다. 후속 실행은 같은 CLI 세션을 재개하더라도 새로운 집계 단위다. 뒤늦게 도착한 하위 사용량은 원래 집계 단위에 반영한다.
- 현재 `thread_total.rs`는 누적값 차이를 저장하는 출발점으로 재사용하되 그대로 일반화하지 않는다. DB 실패 시 전체 값을 반환하는 동작과 90일 기준 삭제는 정확한 전체 트리 집계에 맞지 않는다. 원본을 남기고 불완전 상태로 재처리한다.

### Claude

최종 result의 모든 `modelUsage` 항목을 합친 전체 트리 누적값에서 직전 세션 누적값을 뺀다. `usage`와 하위 로그를 여기에 다시 더하지 않는다. 여러 모델을 사용한 세션도 같은 원칙을 쓴다.

`modelUsage`가 없으면 부모 `usage`만 보존하고 하위 포함 여부를 미확인으로 표시한다. 오류 result도 사용량이 있으면 반영한다. result 없이 종료되면 확보한 부분 사용량만 남긴다. 백그라운드 하위 작업의 종료가 확인되지 않은 결과를 완전한 집계로 표시하지 않는다.

공식 문서도 `usage`는 하위 작업을 제외하고 `modelUsage`는 포함하며, 재개 시 누적값이라고 설명한다. [Claude 사용량 문서](https://code.claude.com/docs/en/agent-sdk/cost-tracking)

### Codex

현재 `exec`의 부모 사용량에 더해, 해당 실행의 CODEX_HOME에서 부모 관계가 확인된 자식·손자 세션의 사용량을 수집한다. 세션 ID를 중복 제거하고 반복되는 `token_count` 알림을 다시 더하지 않는다. 상속된 대화 이력과 실제 자식 요청의 사용량은 구분한다. 파일 생성 시각이나 같은 폴더라는 이유로 세션을 귀속시키지 않는다.

이미 있는 `exec` 및 총괄 `app-server` 실행 경로를 유지한다. app-server가 보고하는 턴 증분에는 세션 누적 차감을 다시 적용하지 않는다. 어느 경로든 부모 보고에 하위 사용량이 포함되는 버전이라면 별도 자식 합산과 동시에 쓰지 않도록 보고 범위를 구분한다.

실행 중에는 대상 세션의 새 기록만 읽고, 종료 시와 중단 복구 시 다시 맞춘다. 날짜를 넘긴 실행도 포함한다. 세션 메타데이터를 한 번 색인한 뒤 관련 파일만 따라가며, 화면 갱신마다 전체 사용자 기록을 훑지 않는다. 공식 CLI가 제공하는 더 안정적인 자식 조회 기능이 검증되면 수집 부분만 교체할 수 있다.

수집은 O 실행기에서 수행한다. 카드에 다른 세션 접근 권한을 추가하지 않는다. 실행 프로필의 세션 위치와 부모 관계를 검사하고 인증 파일이나 대화 본문을 집계 결과에 복사하지 않는다. 로그가 없거나 형식을 모르면 확인된 부분과 누락 사유를 표시한다. 하위 목록의 완전성을 증명할 수 없는 CLI 버전은 '완전'으로 처리하지 않는다.

## 결정 2: 기존 기록과 새 기록을 같은 방식으로 보정한다

원시 CLI 로그와 기존 이벤트는 보존한다. `card.usage`와 `lead.usage`의 기존 증분 의미도 바꾸지 않는다. 보정 가능한 최종값은 별도의 사용량 정산 이벤트로 남기고, 최신 정산값이 지정한 집계 단위의 기존 값들을 **대체**하게 한다.

정산 이벤트의 최소 계약은 다음과 같다. Rust/TypeScript의 최종 타입 이름은 구현 시 기존 이벤트 관례를 따른다.

| 항목 | 의미 |
|---|---|
| `usageId`, `revision` | 동일 실행 시도/총괄 턴의 수정본. 같은 수정본은 한 번만 반영한다. |
| 대상 카드/턴 및 원본 보고 참조 | 무엇을 대체하는지 명시한다. 기존 기록은 이벤트 순번으로 식별할 수 있다. |
| `occurredAt`, 기록 시각 | 원래 사용 시각과 보정 시각을 구분한다. 과거 사용량이 오늘 사용량으로 이동하지 않는다. |
| `input`, `cached`, `output` | 해당 단위의 권위 있는 최종값 또는 확인된 부분값. 추가할 차액이 아니다. |
| 확인 상태·사유 및 보고 범위 | 하위 포함·부분 확인·자료 없음의 차이를 보존한다. |
| 원본 식별자·집계 버전 | 같은 입력을 재처리했는지 판단하고 근거를 추적한다. 원문 대화는 저장하지 않는다. |

이벤트를 먼저 내구성 있게 기록하고 o.db는 재생성 가능한 색인·집계 상태로 사용한다. DB 기준값을 먼저 갱신한 뒤 이벤트 쓰기에 실패해 사용량이 사라지는 이중 쓰기 구조를 만들지 않는다. 재시도와 동시 실행은 동일 ID·수정본의 중복 처리 방지 및 기존 이벤트 쓰기 잠금 안에서 처리한다. 같은 수정본에 다른 내용이 오면 오류로 남긴다.

정산 이벤트 이후 오래된 프로그램은 이를 무시할 수 있으므로 업그레이드된 앱·o.exe를 함께 배포한다. 이전 버전으로 내려가도 원본을 잃지는 않지만 새 보정 합계는 보이지 않을 수 있다.

기존 기록 보정은 별도 정비 명령 `o tokens reconcile`을 제안한다. 기본은 변경 없는 예상 결과이며, 프로젝트/실행 범위와 `--apply`를 명시하면 정산 이벤트를 추가한다. 적용은 기존 O 상태 보호 규칙에 따라 사람 실행 경계에 둔다. 앱 갱신 때 몰래 모든 기록을 수정하지 않는다. 원본이 부족한 기록은 추정값으로 덮지 않는다. 진행 중인 실행은 실행기의 정산에 맡기고, 과거 보정에서는 제외한다.

프로젝트 합계·실행 합계·카드 합계·총괄 합계·`o tokens`가 같은 정산 규칙을 사용해야 한다. 일일 예산은 현재 공급자의 구독 사용률을 기준으로 하므로, 이 토큰 보정값으로 예산 방식을 바꾸지 않는다.

## 결정 3: 모델 목록을 실행 환경에 맞춰 조회한다

기존 `ModelChoice`와 모델 조회 경로를 확장해 총괄·작업 카드·CLI·개발 서버가 동일한 출처를 사용한다. 모델별 실행 ID, 표시명, 해석된 모델 ID, 지원 effort, 조회 시각과 최신 확인 여부만 전달한다.

- Claude: 고정 버전표를 제거하고, 공식 CLI 초기화 응답의 모델 메타데이터를 읽는 방안을 먼저 검증한다. 공식 SDK의 `initializationResult().models` / `supportedModels()`와 같은 데이터다. 응답에는 계정 정보도 있으므로 필요한 모델 필드만 추출하고 전체 응답을 로그에 남기지 않는다.
- Codex: 기존 `debug models`를 유지하되 실제 실행과 같은 프로필·작업 폴더·CLI 경로로 조회하고 모델별 effort 정보를 보존한다.
- OpenCode 등 기존 카드 전용 조회도 같은 데이터 계약에 연결한다. 조회가 금지된 프로바이더를 새로 조회하거나 터미널 카드에 모델·effort 강제를 추가하지 않는다.

Claude 메타데이터의 공식 지원 필드는 `value`, `resolvedModel`, `displayName`, `supportedEffortLevels`다. SDK 전체를 도입하거나 작업 실행 경로를 SDK로 바꾸는 것을 이번 변경의 전제로 삼지 않는다. **현재 설치 CLI에서 사용자 프롬프트·모델 생성 없이 초기화 조회가 끝나는지는 구현 첫 단계에서 검증해야 한다.** 지원하지 않으면 버전 미확인 별칭 또는 마지막 성공 목록을 표시한다. 별칭을 최신 버전이라고 추측하지 않는다. [공식 타입 문서](https://code.claude.com/docs/en/agent-sdk/typescript#modelinfo)

캐시는 o-core에서 공유한다. 키는 provider·실행 프로필·작업 폴더·CLI 경로/버전이며, 기존 10분 TTL을 유지한다. 앱에서 목록을 열거나 다시 활성화할 때, 계획을 만들 때 만료된 목록을 갱신한다. 프로필 전환·앱에서 수행한 로그인·CLI 업데이트 뒤에는 무효화한다. 같은 키의 동시 조회는 합친다. 외부에서 바뀐 로그인·설정은 TTL을 통해 재확인한다.

조회 실패 시 마지막 성공 목록과 갱신 실패를 함께 제공한다. 자동으로 다른 모델을 선택하거나 대표님의 저장된 총괄 모델·effort를 바꾸지 않는다. 직접 공급자 서버 호출이나 인증 파일 열람은 하지 않는다.

## 결정 4: 계획의 모델 선택과 실제 실행 모델을 구분한다

1. 총괄 계획 입력에 사용 가능한 worker 모델 ID와 지원 effort를 간결하게 제공한다. 매번 긴 설명 전체를 넣지 않고 후보 목록과 변경 사항만 전달한다. 모델 조회 때문에 LLM을 별도로 호출하지 않는다.
2. 새 자동 생성 계획의 헤드리스 카드는 `model`과 `effort`를 명시한다. 모델을 비우라는 지시와 생략된 예시를 수정한다. 독립적인 작은 수정·조사·복잡한 구현·통합 검토의 요구를 보고 후보 중에서 고르도록 하고, 모든 카드의 동일한 기본값을 암묵적으로 사용하지 않는다. 서로 다른 모델을 억지로 섞도록 강제하지는 않는다. 터미널 카드는 기존 CLI 설정 사용 규칙을 유지한다.
3. 대표님이 지정한 값이 우선이다. 자동 선택은 카탈로그의 성능·용도 정보와 작업 요구를 근거로 하며, 알 수 없는 가격 순위를 지어내지 않는다. 선택 이유는 총괄의 기존 계획 설명에 한 줄로 적고 새 라우팅 엔진은 만들지 않는다.
4. 기존·수동 계획의 `model` 생략은 호환성을 위해 CLI 기본 의미를 유지한다. 새 총괄 계획의 헤드리스 카드에서 모델이 빠지면 계획 검사를 통과시키지 않는다. 조회 실패 때는 마지막 성공 목록이나 명시된 사용자 선택을 쓸 수 있지만, 선택할 근거조차 없으면 해당 카드가 미완성인 이유를 반환한다. 백엔드가 임의의 상위 모델이나 암묵적 기본 모델을 넣지 않는다. 총괄 자신의 'CLI 기본' 선택은 그대로 유지한다.
5. 계획 저장·실행 시 모델 ID 형식, 해당 provider, 지원 effort를 확인한다. 목록은 사용 가능 모델을 완전히 보장하지 않으므로 기존 사용자 지정 모델을 목록에 없다는 이유만으로 삭제하지 않는다. 명시된 모델을 CLI가 거부하면 실패 사유를 보여 주고 기본 모델로 재시도하지 않는다.
6. `card.model`은 요청값으로 보존하고, 실행 세션에서 보고한 실제 모델은 별도 기록한다. Claude 초기화/메시지와 Codex thread/turn 기록을 사용하며 확인할 수 없으면 미확인으로 남긴다. 별칭 해석, 모델 변경, 하위 에이전트가 다른 모델을 사용한 경우도 실제 관측값으로 구분한다.
7. 모델 목록 갱신은 이미 실행 중이거나 승인된 계획의 선택을 바꾸지 않는다. 후속 실행도 명시적인 변경 요청이 없으면 기존 세션의 선택을 보존한다. effort의 요청값·실행 인자와 기존 예산 조정 이벤트를 구분하며, CLI가 실제 effort를 보고하지 않으면 확인했다고 표시하지 않는다.

## 영향과 남은 불확실성

- 사용량 표시가 늘어나는 것은 기존 누락의 복구다. 집계 수정 자체가 실제 토큰 소비를 줄이지는 않는다. 자동 모델 선택의 절감 효과도 작업 품질·실측으로 확인해야 한다.
- 하위 에이전트의 수·권한·동시 실행 제한, 총괄 자동 응답 정책, 일일 예산 기준은 이번 수정에서 바꾸지 않는다. 이들은 별도의 사용량 절감 결정이다.
- Codex 세션 로그 형식은 CLI 버전 변경의 영향을 받는다. 실제 관측 형식과 불완전 표시를 함께 유지해야 한다. 로컬 기록이 삭제된 과거 사용량은 완전히 복구할 수 없다.
- Claude의 모델 목록 데이터 계약은 공식 문서로 확인했으나, 현재 설치 CLI에서 추론 없이 조회하는 연결은 아직 실행 검증하지 않았다. 이를 통과하기 전 자동 최신화 완료로 보고하지 않는다.
- 원본 보존과 기존 로그 읽기는 호환된다. 새로운 정산 이벤트를 모르는 구버전 앱의 보정 합계 표시까지 보장하지는 않는다.

## 추가 결정: 구독 한도 자동 전환 — 기본 OFF

대표가 2026-11-12 추가로 요청했다. 현재 설치 실행파일에서 Codex만 시험하고 설계를 보완하는 단계이며, 아래 기능은 아직 구현하지 않았다.

### 사용자 설정 계약

설정 → 에이전트에 구독 한도 자동 전환 ON/OFF, 대체 에이전트, 대체 모델을 둔다. 기존 설정 컨트롤을 재사용하며 이 문서는 화면 배치·스타일을 새로 정하지 않는다.

- 기본값은 `subscriptionFallback: { enabled: false, target: null }`이다. 저장된 값이 없거나 잘못되어도 OFF다.
- 대상은 사용자가 `{ provider, model }`로 지정한다. 임의로 채우거나 모델을 암묵적 기본값으로 넘기지 않는다. ON인데 대상 또는 모델이 없으면 저장하지 않고 누락 항목을 알린다.
- OFF로 바꿔도 대상 선택은 보관할 수 있지만 새로운 전환은 시작하지 않는다. o-core의 기존 settings.json 저장 경계를 사용하고 앱·CLI·개발 서버가 같은 검증을 한다.
- 계획이나 에이전트가 이 설정을 켜거나 대상을 바꿀 수 없다. ON은 이미 승인한 동일 작업을 지정 대상으로 이어 실행하는 동의이며 새 과제를 자동 승인하는 뜻이 아니다.

### 발동 조건

공식 CLI의 구조화된 구독 사용률/오류 또는 명확한 구독 한도 문구로 확인된 경우만 전환한다. 확인된 구독 쿨다운으로 시작 전에 막힌 경우와 실행 도중 한도가 소진된 경우를 포함한다.

현재 `providers/stream.rs`의 Limit 신호는 구독 한도·분당 제한·크레딧 부족을 충분히 구분하지 못하고 `run/store.rs`의 cooldown은 provider와 해제 시각만 보관한다. 원인 분류를 먼저 추가한다. 기존 원인 미상 cooldown은 차단을 유지하되 자동 전환 근거로 쓰지 않는다. 해제 시각이 없는 명확한 구독 오류는 원인과 시각 미상을 구분해 보존한다.

`profile-not-ready`, 로그인 실패, 권한 거부, 일일 예산, 네트워크 오류, 일반 429, 분당 제한, API 크레딧 부족, 컨텍스트·출력 크기 초과, 다른 정책 위반은 전환하지 않는다. 이번 시험의 샌드박스 재점검 요구도 구독 차단이 아니다.

### 실행과 중복 방지

1. OFF이면 기존 실패·대기 동작을 유지한다. ON이고 구독 차단이 확인되면 지정된 대상 하나만 읽는다.
2. 원래 서비스와 같은 provider이면 전환하지 않는다. 같은 서비스의 모델·계정을 바꿔 구독 한도를 피하지 않는다.
3. 대상의 역할 지원, 설치·로그인·프로필 준비, 모델/effort, 쿨다운·일일 예산, 과금 모드, 권한, 작업 폴더·동시 실행·자원을 다시 검사한다. 총괄 미지원 에이전트는 카드에만 사용할 수 있고 총괄 전환은 사유와 함께 멈춘다. 터미널 방식은 이번 자동 전환 대상에서 제외한다.
4. 원래 effort를 지원하면 그대로 전달한다. 미지원 값을 임의 매핑하거나 올리지 않고 전환 불가 이유를 표시한다. 프로필·권한·과금 정책은 바꾸지 않는다.
5. 원래 프로세스가 종료된 것을 확인한 뒤 대체 프로세스를 시작한다. 자원 예약이 겹치지 않게 넘기고 기존 작업 폴더·변경 파일을 보존한다.
6. 서로 다른 provider 사이에 세션 ID를 재사용하지 않는다. 원래 요청·완료/미완료 부분·관련 파일·마지막 결과를 한정해 새 세션에 전달한다. 전체 로그 복사나 별도 요약 모델 호출은 하지 않는다. 이미 한 작업을 다시 실행하도록 만들지 않는다. 외부 작업의 성공 여부처럼 안전한 인계를 확인할 수 없는 상태는 자동 전환을 중단하고 이유를 알린다.
7. 같은 논리 작업에는 대체 실행을 **최대 한 번** 한다. 대상도 막히면 다른 모델·서비스를 임의 순회하지 않는다. 원래 서비스 한도가 풀려도 진행 중인 대체 작업을 되돌려 옮기지 않는다. 새 작업은 원래 선택을 다시 따른다.
8. 전환 직전에 설정을 다시 읽는다. OFF면 대기 중인 전환을 취소한다. 이미 시작한 대체 작업을 OFF만으로 강제 종료하지 않는다.

원래 계획을 덮어쓰지 않는다. 총괄·카드 전환 이벤트에 원래/대체 provider·model, 원인, 한도 해제 시각(알 때만), 전환 시각·실행 시도를 남긴다. 실패한 원래 시도와 대체 시도의 사용량을 각 실제 provider/model에 귀속하고 논리 작업 합계에서 둘 다 한 번씩 센다. 재시작 뒤에도 같은 전환을 두 번 실행하지 않아야 한다.

### 변경 범위와 검증

기존 사용량·모델 변경 범위에 Limit 원인 분류, cooldown 저장, 공통 설정, 총괄·카드 대체 실행과 인계, 전환 이벤트, CLI/Tauri/개발 서버 설정 계약을 추가한다. 가드·설정·분배 경계가 바뀌면 관련 ADR·검사도 함께 수정하며 기존 보호 규칙은 완화하지 않는다.

| 사례 | 기대 결과 |
|---|---|
| 기본값/설정 없음/OFF + 구독 한도 | 대체 CLI 호출 0회 |
| ON + 유효한 사용자 지정 대상 + 구독 한도 | 지정 모델로 한 번 전환, 원래/대체 사용량 모두 보존 |
| 준비 오류·권한 거부·예산·속도 제한 | 전환 0회, 실제 사유 표시 |
| 대상도 한도/같은 provider/역할 미지원 | 순환·다른 계정 우회 없이 중단 이유 표시 |
| 중복 알림·동시 알림·재시작 | 동일 논리 작업의 대체 실행 한 번 |
| 부분 작업·불명확한 외부 실행 | 변경 보존, 확인 가능한 안전한 인계만 수행 |
| 전환 대기 중 OFF | 새 전환 취소; 이미 실행 중인 작업은 유지 |

## 설치 실행파일 Codex 시험 반영

시험은 대표가 선택한 범위대로 제품 코드를 고치지 않고 설치 앱의 o.exe로 수행했다. [시험 보고서](../reports/2026-11-12-codex-smoke.md)

- 처음 두 카드가 `profile-not-ready`로 거부됐다. 대표 요청으로 공식 샌드박스 재점검을 실행해 통과한 뒤 같은 계획을 실행했다. 권한·프로필 변경으로 우회하지 않았다.
- 총괄 GPT-6.1-Sol/medium 1턴, 기본 모델 카드 GPT-6.1-Sol/medium, 명시 모델 카드와 하위 1개 GPT-6.1 Terra/medium 모두 정상 완료했다. 명시 모델 전달 자체는 정상이다.
- 실행 `20261112-070527-vock`의 앱 프로젝트 합계는 128,622이지만 하위 64,369가 빠졌다. 확인된 전체 합계는 192,991토큰이다. 별도 샌드박스 재점검 사용량은 이 합계에 포함하지 않는다.
- 부모·자식 세션별 첫 누적값과 첫 요청 사용량, 중복 알림을 제거한 요청 합계와 최종 누적값이 일치했다. 앱은 부모만 집계하면서도 두 카드를 `complete: true`로 표시했다. 하위 수집과 완전성 판정을 함께 고쳐야 한다.
- 카드 원본 변경과 남은 자원 예약은 0이다. Claude 호출, 새 자동 전환·정산 구현, GUI 버튼 실행, 배포는 검증 범위에 넣지 않았다.

## 구현 계약과 확인 범위

- `usage/accounting.rs`의 `usageId`는 실행·카드·provider·시도 순번 또는 총괄 턴을 식별한다. `revision`의 최신 값만 합산한다. `card.usage.settled`·`lead.usage.settled`는 최초 실행 시각, 원본 바이트 범위, 실제 프로필, 누적 기준값, 실제 모델, 불완전 사유를 보관한다. 옛 이벤트 대체 참조는 종류·시각·카드·provider·중복 순번으로 만들므로 모르는 이벤트를 제외해도 유지된다.
- 원시 출력과 잠근 `usage-journal.jsonl`을 먼저 보존하고 `events.jsonl`·SQLite 인덱스로 전달한다. SQLite와 분리된 저널에서 재개 기준값을 읽으며 90일 제한을 두지 않는다. 이벤트 전달 전에 중단된 저널 기록은 명시적 보정으로 복구한다. SQLite는 정산값을 다시 합산하는 인덱스다.
- `o tokens reconcile --run <실행ID>` 또는 `--project <폴더>`는 기본 미리보기이며 DB를 읽기 전용으로 연다. 사람이 `--apply`를 붙여야 기록을 바꾼다. 원본·재개 기준값·턴 경계가 없는 옛 기록은 기존 수치를 남기고 보정 불가 사유를 출력한다. 옛 총괄 기록의 턴 경계를 추측하지 않는다. 실행 중이거나 자원 예약이 남은 기록은 보정하지 않는다.
- Codex는 실제 `CODEX_HOME/sessions`의 명시적 부모 연결을 모든 깊이로 읽는다. 처음 상속한 누적값과 중복 보고를 빼고, 원래 시도 시간 구간에 속한 늦은 하위 기록을 같은 정산의 새 revision으로 반영한다. app-server의 턴 delta에는 누적값 차감을 다시 하지 않는다. 공식 기록에 전체 자손 목록의 완전성 보증이 없어 확인된 Codex 트리도 부분 집계로 표시한다.
- 모델 목록은 실제 프로필·작업 폴더·CLI 실행 파일/스크립트 식별자로 나누고 10분간 캐시한다. 실패 시 이전 목록과 시각을 유지하고 stale/error를 알린다. Claude 초기화 메타데이터가 없으면 버전 미확인 alias만 제공한다. 이번 구현 검증에서 실제 Claude CLI는 호출하지 않았다. Antigravity·Devin의 자동 모델 조회는 지원하지 않는다.
- 새 총괄 생성 headless 계획만 `model`·`effort`를 필수로 검증한다. 기존·수동 계획과 터미널 카드는 이전 계약을 유지한다. 화면의 요청 모델과 `actualModels`는 별도 값이고 `usageComplete`로 부분 집계를 표시한다.
- `subscriptionFallback`은 기존 공통 설정에 기본 OFF로 둔다. CLI `o fallback`, Tauri `fallback_get`·`fallback_set`, 개발 서버 `/api/fallback`이 같은 코어 검증을 쓴다. 쓰기는 에이전트 표식과 Windows 작업 개체 판정으로 거부한다. 원인 미상 cooldown은 전환 근거가 아니며 일반 한도 보고가 들어오면 기존 구독 원인 증거를 지운다.
- 자동 전환은 다른 provider의 명시 모델로 한 번만 한다. 자원 예약·승인·실행 프로필·effort·예산·과금·설치/로그인 상태를 다시 확인한다. 격리 실행의 정책 검사는 원래 검증한 프로젝트 경로를 쓰고 실제 작업 폴더는 그대로 유지한다. 실행 직전 OFF 변경은 새 프로세스 시작을 막는다. 알 수 없는 셸·MCP·외부 작업 결과나 살아 있는 프로세스가 있으면 인계하지 않는다. provider가 바뀌면 세션 ID를 재사용하지 않는다.

검증과 제한은 [구현 검사 기록](../reports/2026-11-12-usage-accounting.md)에 적는다. 설치 앱의 실제 과거 수치와 구독 한도 전환을 새 코드로 재실행한 것으로 해석하지 않는다.
