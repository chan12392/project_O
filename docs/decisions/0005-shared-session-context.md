# ADR-0005: 세션 공유 — 프로젝트 컨텍스트 검색과 카드 주입

- 상태: 제안 (대표 요청으로 구현, test_2에서 확인 후 승인)
- 날짜: 2026-11-02
- 승인: [ ] A  [ ] B
- 관련: ADR-0002(카드 권한), `AGENTS.md` 프로바이더 정책 자동 차단, `docs/token-benchmark.md`

## 배경

카드를 맡길 때마다 각 CLI는 사용자 하네스(AGENTS.md·USER·MEMORY 같은 전역 지시, 훅, 스킬)를 통째로 읽는다. 일의 크기와 상관없이 매번 같은 기본 컨텍스트에 토큰을 쓰고, 정작 같은 프로젝트에서 앞서 다른 카드가 알아낸 것은 모른다.

목표는 토큰 사용 최적화다. 깨끗한 에이전트(`o dispatch --clean`, 하네스 없음)에 **그 카드의 일과 관련된 이전 작업 몇 줄만** 넣고, 더 필요하면 카드가 스스로 찾게 한다.

## 선택지

1. 이전 실행의 결과를 통째로 프롬프트에 붙인다 — 실행이 쌓일수록 커져 목표와 반대다.
2. 별도 메모리 서비스(MCP 등)를 카드에 연결한다 — 깨끗한 프로필 원칙(MCP 없음)과 맞지 않고 설치가 필요하다.
3. O의 실행 색인(`o.db`)에 전문 검색을 두고, 카드 일에 맞는 조각만 상한 안에서 주입하며, 카드에는 읽기 전용 검색 명령만 연다.

## 결정

3을 고른다.

- **저장**: `o.db`에 FTS5 표 `context_fts`(제목·본문·파일 | 프로젝트·실행·카드·종류·시각)와 진행 표 `context_seen`을 둔다. 종류는 `result`(완료된 카드의 `card.end` 결과), `message`(팀 대화), `note`(`o context add`). 실행 색인을 갱신한 뒤 새로 들어온 이벤트만 읽어 넣는다(같은 쓰기 잠금 안에서 진행 위치를 확인해 두 번 넣지 않는다). 실행 폴더가 사라지면 그 실행의 항목도 빠지고 메모는 남는다. 프로젝트 경로는 색인과 같은 방식(`/`, 끝 `/` 없음, Windows는 대소문자 무시)으로 맞춘다.
- **검색**: bm25 순위. 한국어는 조사가 붙어 있어(`캐릭터를`) 질문의 각 낱말에서 흔한 조사를 떼고 접두어로 찾는다(`"캐릭터"*`). 실패 실행의 결과는 넣지 않는다(권한 거부·한도 같은 잡음).
- **주입**: 실행이 시작될 때 카드마다 카드 `task`로 같은 프로젝트를 검색해, 상위 조각을 **최대 1,500자**(`context::INJECT_CHARS`, 한 조각 600자)까지 작업 내용 바로 뒤에 `관련 컨텍스트 (이전 작업에서):` 절로 넣는다. Claude·Codex 카드에는 `o context "<질문>"`으로 더 찾을 수 있다는 한 줄을 붙인다. 그 밖에는 아무것도 더하지 않는다. 넣은 카드가 있으면 `run.context { cards, chars, cardIds }` 이벤트를 남긴다. `o dispatch --no-context`는 주입하지 않는다(A/B 기준선).
- **카드 권한 (넓어지는 부분)**:
  - Claude: `--allowedTools "Bash(o msg *)" "Bash(o context *)"` — `o context` 한 명령이 더 열린다.
  - Codex: 바꾸지 않는다. 이미 샌드박스 안에서 셸 명령을 실행하므로 `o context`를 그대로 쓸 수 있다.
  - Antigravity: 허용 규칙이 전체 일치만 받아 자유 질문을 담은 고정 명령을 만들 수 없다. 열지 않고 주입된 절만 쓴다(그 카드에는 "더 찾기" 줄도 넣지 않는다).
- **카드 안에서는 읽기 전용**: `O_CARD_ID`가 있으면 `o context`는 `o.db`를 읽기 전용으로 열고 색인을 갱신하지 않는다(카드는 o.db를 쓰지 않는다는 ADR-0002 원칙 유지). WAL 보조 파일을 만들 수 없는 샌드박스에서는 마지막으로 기록된 파일 내용을 읽는다. `o context add`는 카드 안에서 거부한다 — 카드가 다른 카드의 프롬프트에 들어갈 글을 심지 못하게 하기 위해서다.
- **측정**: `o tokens [--project] [--since] [--compare] [--json]`이 `card.usage`를 카드·실행별로 더하고, 실행 방식(기본 / `--clean`)과 컨텍스트 주입 여부로 묶어 카드당·프로바이더별 평균을 낸다. `--compare`는 "기본 하네스"(기본, 주입 없음)와 "깨끗한+세션 공유"(`--clean`, 주입됨)를 나란히 보여 준다. 앱 대시보드에 같은 내용의 "토큰" 카드를 둔다.

## 남은 위험

- 이전 카드의 결과 글은 카드가 쓴 것이다. 주입되면 다음 카드에게 지시처럼 읽힐 수 있다. 상한(1,500자)과 같은 프로젝트로 범위를 묶고, 카드는 메모를 추가하지 못하게 했지만, 결과 글 자체를 거르지는 않는다. 팀 메시지와 달리 정책 검사(`team::send`)도 거치지 않는다.
- Claude 카드의 `Bash(o context *)`는 `o context add …`와도 문자열이 맞는다. 이 경우 CLI가 카드 안이라 거부한다(환경변수를 지우는 형태는 규칙과 맞지 않아 승인이 필요하고, 헤드리스라 거부된다).
- 실행 색인이 같은 실행을 처음부터 다시 읽었는데 이벤트 수가 오히려 늘어난 경우(파일을 손으로 고친 경우)는 감지하지 못해 그 실행의 앞부분 항목이 빠질 수 있다. 실행 폴더를 지우면 다시 맞춰진다.
- 카드 안의 `o context`는 색인을 갱신하지 않으므로, 같은 실행에서 방금 끝난 다른 카드의 결과는 누군가(앱, `o runs`, 다음 dispatch)가 색인을 갱신해야 보인다.

## 영향

- 바뀐 공용 경계: 카드 CLI 권한(Claude 한 명령 추가), 이벤트 계약(`run.context` 추가 — 모르는 화면은 무시한다), 카드 프롬프트(절 하나).
- 코드: `crates/o-core/src/context.rs`(+`context/tokens.rs`), `providers.rs`(허용 명령·프롬프트 절), `runner.rs`(실행 시작 시 `context::prepare`), `o context`·`o tokens`·`o dispatch --no-context`, 앱 `tokens` 명령과 대시보드 토큰 카드.
- 되돌리기: `o.db`의 두 표를 지워도 실행 기록(events.jsonl)에서 다시 만들어진다(메모만 사라진다). 권한은 `providers.rs`의 한 줄을 빼면 된다.
