# ADR-0037: 카드 동시 실행 우선과 카드 안의 서브에이전트

- 상태: 채택
- 날짜: 2026-11-09
- 관련: [ADR-0002](0002-security-hardening.md), [ADR-0004](0004-daily-usage-budget.md), [ADR-0008](0008-lead-chat.md), [ADR-0015](0015-opencode.md), [ADR-0016](0016-devin.md), [ADR-0020](0020-antigravity-policy.md)

## 배경

총괄이 설계한 계획을 전달하면 화면에는 카드가 모두 함께 일하는 것처럼 보였지만 실제로는 하나씩 돌았다. 실행기(`run/runner.rs`)는 카드마다 스레드를 띄우는 병렬 구조이고, 카드를 기다리게 하는 것은 세 가지다: 끝나지 않은 `depends_on`, 겹치는 `resources`(선언하지 않은 카드는 모든 카드와 겹친다고 본다), 동시 실행 상한. 2026-11-09 실행 `20261109-123716-tent`는 총괄이 `core → gui → package → review`를 `depends_on` 사슬로 묶어 네 단계로 돌았다. gui는 core의 결과가 아니라 인터페이스(`CleanOptions`, `clean()`)만 있으면 됐다. 화면의 "누가 무엇을" 패널은 `queued`도 "작업 중"으로 세고 같은 강조를 붙였다.

카드 하나 안에서도 Claude Code와 Codex는 서브에이전트로 일을 나눌 수 있다. Claude Code의 Agent 도구는 권한을 묻지 않고, 서브에이전트는 카드의 권한 모드(`acceptEdits`, 허용 명령 `o msg`·`o context`)를 그대로 쓴다. Codex의 서브에이전트(`multi_agent`)는 안정 기능이지만 기본으로 꺼져 있다(`codex features list`, codex-cli 0.167.0).

## 결정

- 총괄 지시문과 `skills/o`는 동시 실행을 기본으로 둔다. `depends_on`은 앞 카드의 실제 결과가 있어야 시작할 수 있을 때만 쓰고, 인터페이스만 필요하면 그 약속을 양쪽 task에 적어 함께 돌린다. 모든 카드에 `resources`를 선언하게 한다. 카드는 서로 다른 파일 영역 단위로 크게 나누고 카드 안의 일은 서브에이전트에 맡긴다.
- `Provider::subagent_tool`이 있는 CLI의 카드 프롬프트에 서브에이전트로 하위 작업을 동시에 나누라는 한 줄을 더한다. 같은 파일을 두 서브에이전트가 고치지 않게 한다.
  - Claude: Agent 도구. 실행 인자는 그대로다.
  - Codex: 카드 실행(기본·YOLO)에 `--enable multi_agent`를 더한다. 서브에이전트는 카드의 샌드박스·승인 설정을 그대로 쓴다. 총괄 실행에는 더하지 않는다.
  - OpenCode·Devin·Antigravity: 이번에는 더하지 않는다. OpenCode v2 프로필 권한 규칙에서 서브에이전트 동작 이름을 확인하지 못했고, 프로필 파일은 처음 한 번만 쓰여 기존 프로필에 반영되지 않는다. Devin은 서브에이전트를 확인하지 못했다. Antigravity는 보류 중이다(ADR-0020).
- 화면은 실행 중인 카드만 "작업 중"으로 세고, 차례를 기다리는 카드는 따로 사유와 함께 보인다. 실행 전 계획 카드에는 `depends_on`으로 나뉜 단계와 자원을 선언하지 않아 혼자 도는 카드를 한 줄로 보인다(동시 실행 상한과 자원 겹침은 실행 때 정해지므로 세지 않는다).
- 정책 한도(`LIMITS`)와 자원 충돌 규칙은 바꾸지 않는다. 서브에이전트는 O가 세는 카드나 슬롯이 아니며, 사용량은 카드의 CLI 사용량에 포함된다.

## 이유

카드 수와 슬롯은 한도로 묶여 있으므로, 같은 한도 안에서 일을 더 빨리 끝내려면 카드끼리는 겹치지 않게 함께 돌고 카드 안에서 다시 나누는 편이 낫다. 사람이 실행 전에 계획이 몇 단계로 도는지 볼 수 있어야 직렬 계획을 고쳐 달라고 할 수 있다.

## 결과

- 서브에이전트는 토큰을 더 쓴다. 하루 예산(ADR-0004)과 사용량 한도는 카드 단위로 그대로 걸린다.
- `multi_agent`를 모르는 옛 Codex에서는 카드가 시작하지 못할 수 있다. 그때는 Codex를 업데이트한다.
- 확인: 카드 프롬프트·Codex 실행 인자 테스트(`crates/o-core/tests/providers.rs`, `context.rs`), 계획 단계 계산 테스트(`tests/planOrder.test.ts`).
