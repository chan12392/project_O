# ADR-0009: 프로젝트 목록 — 프로젝트 루트 폴더와 등록한 폴더만 왼쪽에 보인다

- 상태: 승인 (2026-11-02 — 대표 요청으로 구현과 함께 작성. 화면 최상위 구조를 바꾼다)
- 날짜: 2026-11-02
- 승인: [x] A  [ ] B (사후 확인 필요)
- 관련: ADR-0002(작업 폴더 정책), ADR-0007(모듈 구조), ADR-0008(총괄 채팅), [ARCHITECTURE.md](../ARCHITECTURE.md)

## 배경

왼쪽 목록은 O 실행 기록에 한 번이라도 나온 폴더, 최근 24시간의 Claude Code 세션 폴더, 총괄 대화 폴더를 모두 프로젝트로 보였다. 홈 폴더(`C:/Users/<이름>`), 임시 폴더, 예전 시험 폴더가 실행마다 섞여 길어졌고, 실행 줄마다 카드 하나에 칩 하나("Codex Codex Codex Codex")가 붙었다. 대표 요청: "시험용 폴더는 전부 test로 넘기고, project 폴더를 만들어서 관리하자. Orca처럼 등록할 수 있게 해서 project 폴더 안의 것들은 왼쪽 패널에 뜨게", "세션마다 에이전트가 엄청 많은데 이것도 개선".

함께 정할 것: 목록을 어디에 두는가(앱·개발 서버·CLI가 같은 답을 내야 한다), 어떤 폴더를 막는가, 목록 밖 기록을 어떻게 다루는가, 칩을 어떻게 줄이는가.

## 선택지

1. 지금처럼 기록에서 프로젝트를 만들고, 숨기기 목록만 둔다 — 새 폴더가 계속 저절로 늘어난다.
2. 브라우저 저장소(localStorage)에 등록 목록을 둔다 — 앱 안에서만 보이고 CLI·다른 창과 어긋난다.
3. 프로젝트 루트 폴더 하나를 정해 그 하위 폴더를 자동으로 프로젝트로 보고, 루트 밖 폴더는 Orca처럼 등록한다. 목록은 O 상태 폴더의 `projects.json`에 두고 `o projects`·Tauri 명령·개발 서버 `/api`가 같은 `o-core` 함수를 쓴다.

## 결정

3을 고른다.

### 프로젝트 루트 (`crates/o-core/src/projects.rs`)

- 기본값은 `<홈 폴더>/.project_o/project`(이 PC는 `C:\Users\chan1\.project_o\project`). 사용자 이름을 코드에 적지 않고 `store::user_home()`(Windows `USERPROFILE`)에서 만든다. 설정 → 프로젝트에서 바꾸고 기본값으로 되돌릴 수 있다. 없으면 화면이 먼저 묻고(“루트 폴더 만들기…”, 새 프로젝트를 만들 때 “루트 만들고 진행”) 그때만 만든다.
- 루트의 바로 아래 폴더 하나가 프로젝트 하나다. 점(.)으로 시작하거나 숨김 속성인 폴더, 파일, 링크·정션(홈 폴더를 가리킬 수 있다)은 뺀다.
- 루트의 `test` 폴더는 프로젝트가 아니라 묶음이다. 그 하위 폴더들이 프로젝트이며 왼쪽 목록 맨 아래에 접힌 "test" 묶음으로 보인다(이 PC: `o-audit`, `o-audit-report`, `o-sandbox`, `o-smoke-lead`, `probe`). 새 프로젝트 이름으로 `test`는 쓸 수 없다.
- 루트는 홈 폴더 안에 있다. Claude Code는 시작 폴더 위쪽의 지시 파일을 읽는데, 깨끗한 프로필의 `claudeMdExcludes`는 홈 폴더 자체의 `AGENTS.md`·`CLAUDE.md`·`CLAUDE.local.md`와 `~/.claude/rules/**`만 뺀다. `.project_o\project\<이름>`(또는 `…\test\<이름>`) 깊이에서도 위쪽 폴더는 `.project_o\project\test`·`.project_o\project`·`.project_o`·홈이고, 확인 결과 앞의 세 폴더에는 지시 파일이 없으므로 프로필 코드는 바꾸지 않았다. 누가 그 폴더들에 지시 파일을 두면 `o agents doctor`의 상위 폴더 경고 대상이며, 깨끗한 테스트 프로젝트는 지금처럼 홈 폴더 밖에 두는 것을 권한다(AGENTS.md "깨끗한 에이전트").
- `.project_o`는 O 상태 폴더(`%LOCALAPPDATA%\project_O`), 깨끗한 프로필(`project_O-agents`), 총괄 첨부(`project_O-lead`)와 이름도 위치도 다르다. 제거기의 데이터 삭제 목록(`app/src-tauri/src/uninstall.rs`의 `LOCAL_NAMES`, `%LOCALAPPDATA%` 아래 고정 이름)에 들어가지 않으므로 "앱과 데이터 모두 제거"도 프로젝트 폴더를 지우지 않는다. 지워지는 것은 상태 폴더 안의 `projects.json`(목록)뿐이다.

### 등록한 폴더

- 루트 밖 폴더(예: `C:\Users\chan1\orca\projects\project_O`)는 등록해서 올린다. 데스크톱은 목록 머리글의 `+`가 Windows 폴더 선택 창을 열고, 브라우저 미리보기는 경로 입력칸을 연다. "새 프로젝트"(폴더+ 아이콘)는 루트에 빈 폴더를 만든다.
- 검사는 카드의 작업 폴더와 같은 `policy::check_project`다: 절대 경로, 있는 폴더, 보호 브랜치 거울이 아님, O 상태 폴더 안이나 그 바깥이 아님, 홈 폴더 자체나 그 위가 아님. 정책의 오늘 카드 수·쿨다운은 쓰지 않으므로 `o.db`를 열지 않는다. 루트와 `test` 폴더 자체, 이미 목록에 있는 폴더도 거절한다. 거절하면 사유를 그대로 보인다.
- 경로는 `context::normalize_project`와 같이 `/`로, 끝 `/` 없이 저장하고 Windows에서는 대소문자를 무시해 비교한다(BK3과 같은 규칙). "목록에서 빼기"는 경로만 지우고 폴더·기록은 그대로 둔다. 사라진 등록 폴더는 "폴더 없음"으로 남겨 뺄 수 있게 한다. 루트 안의 폴더는 뺄 수 없다(옮기거나 루트를 바꾼다).
- 폴더 선택 창은 공식 `tauri-plugin-dialog`(=2.8.4, 정확히 고정)를 Rust 명령 `pick_folder`에서만 연다. 화면에 플러그인 JS 패키지를 넣지 않고 capability도 두지 않아, 화면은 대화상자 명령을 직접 부를 수 없고 고른 경로만 받는다(폴더 열기 하나보다 좁다). 등록은 별도 명령이 다시 검사한다.

### 저장과 명령

- `projects.json` (`{ "root": null | "<폴더>", "registered": [...] }`), O 상태 폴더 안. 옆 파일에 쓰고 이름을 바꿔 덮어 반쯤 쓴 목록이 읽히지 않게 한다. 읽지 못하는 파일은 오류로 돌려주고 덮어쓰지 않는다.
- `o projects [list] | add <폴더> | remove <폴더> | new <이름> | root [<폴더>|--default] [--create] | check <폴더>... [--json]`(명령 표 `COMMANDS`), Tauri `projects_list|add|remove|new|root|check`와 `pick_folder`, 개발 서버 `/api/projects[/add|/remove|/new|/root|/check]`, `Backend.projects*`. 데모는 녹화 기록의 폴더를 루트(`C:/projects`)와 test 묶음·등록 폴더 하나로 보여 주고 바꾼 것은 그 창에서만 유지한다.

### 화면

- 왼쪽 목록에는 루트 프로젝트·등록 폴더(최근 활동 순, 총괄 대화 시작도 활동으로 센다), 사용자 그룹, 접힌 test 묶음만 보인다. 실행·총괄 대화·Claude Code 세션은 폴더가 목록의 프로젝트이거나 그 안일 때 가장 깊은 프로젝트에 붙는다. 나머지는 숨길 뿐 지우지 않는다. 전체 "다음 할 일" 화면과 배지도 같은 거름을 따른다. 목록을 읽지 못하면 예전처럼 기록의 모든 폴더를 보이고 그 사실을 적는다.
- 처음(등록 폴더가 없을 때) 한 번만 "기록에서 찾은 프로젝트" 카드를 보인다: 기록·세션·총괄 대화의 폴더 중 목록에 없는 것을 최신 순으로, 임시 폴더는 빼고, 기계가 `check`로 거절한 것(홈 폴더 자체, O 상태 폴더 등)도 뺀다. O 실행이 있던 폴더만 미리 체크하고, 루트의 동작을 함께 설명한다. 등록하거나 닫으면 다시 보이지 않는다(이 브라우저 저장소).
- 프로젝트마다 총괄 줄, 최근 실행 3개, 나머지는 접힌 "이전 실행 N개". 선택한 실행이 그 안에 있으면 7일 안의 것일 때만 저절로 펼치고, 더 오래된 것이면 접힌 줄을 선택 표시로 칠한다.
- 카드 칩: 에이전트마다 한 번(픽셀 얼굴 + "Codex ×4")과 상태별 개수(상태 점 색 그대로)로 줄인다. 실패·총괄 답을 기다림·조용함·한도 걸림 카드는 "다음 할 일"과 같은 판단(`attention.nextUp`)으로 골라 하나씩 남긴다. 묻는 것 없는 보고(완료 보고 등)는 배지와 같이 `isNote`로 "읽을 메모"로 보고 답을 기다림 칩에서 뺀다. 전체 카드 목록은 실행 줄에 마우스를 올리거나 키보드로 초점을 주면 뜨고(최대 12장, 화면 읽기 프로그램은 요약 문장), 선택한 실행은 12장까지 칩을 모두 보인다(오른쪽 패널은 언제나 전체). 사무실 보기의 카드 목록도 7장부터 같은 요약으로 줄인다. 누가 일하나(최근 6장까지)와 전체 다음 할 일(카드별 티켓)은 이미 짧아 그대로 둔다.
- "새 요청"은 입력창 포커스가 아니라 새 요청 화면을 연다: 맡길 프로젝트 고르기, 새 프로젝트 만들기, 다른 폴더 등록. 고르면 그 프로젝트의 총괄 대화로 가서 입력창에 초점을 둔다.

## 영향

- 화면 최상위 구조(왼쪽 목록이 무엇을 보이는가)가 바뀐다. 기록·세션·총괄 대화·색인은 그대로이고, 목록에 넣으면 다시 보인다.
- O 상태 폴더에 `projects.json`이 생긴다. 지워도 기본 루트로 돌아갈 뿐 실행 기록에는 영향이 없다.
- 데스크톱 의존성에 `tauri-plugin-dialog`(와 그 의존성 `tauri-plugin-fs`)가 더해졌다. 화면 권한(capability)은 더하지 않았다.
- 순수 로직은 `src/core/projects.ts`(소속 판단·첫 실행 후보·칩 요약)와 `crates/o-core/src/projects.rs`(목록·검사)에 있고 `tests/projects.test.ts`, `crates/o-core/tests/projects.rs`, `crates/o-cli/tests/projects.rs`가 고정한다.
- 되돌리기: 기능 단위 커밋이므로 되돌릴 수 있다. `projects.json`은 남지만 읽는 쪽이 없을 뿐이다.
