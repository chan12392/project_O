## 배경

O CLI(작업카드 분배)와 정책 차단을 TypeScript로 먼저 만들어 실제 Claude·Codex·Antigravity 병렬 실행까지 확인했다(테스트 포함 약 1,460줄). 데스크톱 앱(채팅 UI·캐릭터 화면)을 올리기 전에 코어 언어를 정해야 한다. 지금 옮기면 비용이 가장 작고, 기존 테스트가 동작 명세 역할을 한다.

## 선택지

1. **전부 TypeScript** — Tauri 셸만 Rust, 코어·CLI는 Node. 빠르게 고칠 수 있지만 사용자 PC에 Node 22.18 이상이 필요하고, 화면 코드가 프로세스 실행 경로에 닿을 수 있다.
2. **Rust 코어 + React 화면** — 정책·실행·이벤트 기록은 Rust 크레이트 하나, CLI(`o.exe`)와 Tauri 백엔드가 같은 크레이트를 쓴다. 화면은 React.
3. **전부 Rust (네이티브 UI: egui·iced 등)** — 단일 언어지만 채팅·마크다운·애니메이션 구현 비용이 크다.

## 결정 (제안)

2번. 이유:

- **차단을 구조로 보장한다.** 에이전트 실행과 정책 검사가 Rust 바이너리 한 곳에만 있으면 화면은 프로세스를 직접 띄울 수 없다.
- **설치가 단순하다.** `o.exe` 하나로 동작하고 Node가 필요 없다.
- **훅이 빠르다.** 에이전트 도구 호출마다 실행되는 훅이 Node(약 0.1초)보다 훨씬 빨리 끝난다.
- **프로세스 관리가 견고하다.** Windows Job Object로 중지 시 자식 프로세스까지 정리하고, 나중에 ConPTY도 같은 곳에서 다룬다.
- **코어 한 벌.** CLI와 앱 백엔드가 같은 코드를 쓴다.
- 화면은 웹 기술이 유리하고 Orchestrator의 React 자산을 재사용할 수 있다.

## 영향

- 저장소 구조(예정): `crates/o-core`(정책·프로바이더·이벤트·상태), `crates/o-cli`(`o` 명령·훅), `app/`(Tauri 2 + React). `src/core/events.ts`의 이벤트 형식은 그대로 유지해 화면 계약을 바꾸지 않는다.
- 이관 순서: Rust로 옮기고 → 현재 테스트와 실제 3개 CLI 병렬 실행을 다시 통과시킨 뒤 → TypeScript 코어를 제거한다.
- 수정 반복이 느려진다(컴파일 대기). CI에 Rust 빌드가 추가되어 몇 분 늘어난다.
- 훅은 빌드된 바이너리가 있어야 동작한다. 빌드 전 상태에서 검사가 조용히 통과하지 않도록 git 훅이 바이너리 부재 시 커밋을 막는다.
- 되돌리기: 이관 완료 전까지는 TypeScript 버전이 남아 있으므로 언제든 1번으로 돌아갈 수 있다.

## 적용 결과 (2026-11-02)

- `crates/o-guard`: 정책 규칙·에이전트 훅(`o hook`)·저장소 검사(`o scan`). 훅은 Node를 띄우지 않고 실행 파일 하나로 끝난다.
- `crates/o-core`: 계획·이벤트·정책·프로바이더 실행/스트림 해석·실행 기록·실행기·사용량 조회. Windows에서 카드 프로세스는 Job Object에 묶여 실행기가 죽어도 남지 않는다. CLI는 셸 없이 띄운다.
- `crates/o-cli`: `o.exe` 하나. 기존 명령에 `o hook`, `o scan`, `o runs --json`, `o usage --cached`, `o sync-mirror`를 더했다. 거울 동기화는 Node 스크립트 대신 `o sync-mirror`.
- TypeScript로 남긴 것: 화면이 쓰는 기록 접기(`src/core/snapshot.ts`)·다음 할 일(`attention.ts`)·타입과 한도 표시값. 개발 서버 API는 직접 파일을 읽지 않고 `o`를 부른다.
- 다음 단계: Tauri 셸에서 `o-core`를 직접 쓰고 개발 서버 API를 Tauri 명령·파일 감시로 바꾼다.

## 단계 3 시작 (2026-11-02)

- `app/src-tauri`(크레이트 `project-o`, 실행 파일 `project_O.exe`): 같은 React 화면을 창 하나로 띄우고 실행 기록·사용량·에이전트 CLI 상태를 `o-core`로 직접 읽는다. 화면은 정해진 Tauri 명령만 부르고 프로세스를 직접 띄우지 못한다.
- 아직 남은 것: 파일 감시(지금은 주기적으로 다시 읽음), 화면에서 작업 전달(`o dispatch`)은 없다. Linux CI는 WebView 라이브러리가 없어 셸 크레이트를 빼고 검사한다.
