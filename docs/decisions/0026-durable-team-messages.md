# ADR-0026: 팀 메시지 저장과 명시적 확인

- 상태: 구현 중 (2026-11-04)
- 관련: ADR-0002, ADR-0022

## 배경

이전 `o msg read`는 출력 전에 수신 개수를 파일에 덮어썼다. 프로세스 종료나 동시 호출은 메시지를 잃거나 중복 전달할 수 있었고, 화면 조회와 에이전트의 처리를 구별하지 못했다.

## 결정

실행 폴더의 `events.jsonl`을 기록으로 유지한다. 메시지는 기존 `msg`에 선택 필드 `id`, `kind`를 추가하고, 별도 `msg.state`로 수신자별 상태를 기록한다. 이전 메시지는 파일의 시작 위치로 ID를 정하고 일반 메시지로 취급한다. 이전 `read.<party>`에 포함된 메시지는 처리 여부를 알 수 없으므로 불명으로 표시하고 자동 재전달하지 않는다. 확인 후 `ack` 또는 `retry`로 진행한다. 기본 읽기는 수신자의 첫 미확인 메시지를 원자적으로 인수하고 불명 상태를 기록하며, `--all`은 상태를 바꾸지 않는 전체 기록 조회다. 인수와 화면 표시는 처리가 아니다.

`o msg send --question`은 질문을 표시한다. `--id`는 발신자 범위의 재시도 키이며 동일 내용 재전송은 기존 ID를 반환하고 다른 내용은 거부한다. 키 없는 전송은 결과가 불명일 때 안전한 중복 제거를 보장하지 않는다. `o msg delivered|unknown|ack|retry|cancel --id <메시지ID>`는 명시적 상태 기록이다. 확인은 수신자별 순서를 따르고, 발신자는 전달을 시작하지 않은 메시지만 취소한다. 불명은 자동 재실행하지 않고 명시적 확인이나 재시도를 기다린다. 이러한 기록은 호출자가 보고한 사실이며 모델 처리의 독립 증거가 아니다.

협력하는 새 O 프로세스는 실행별 OS 파일 잠금으로 모든 이벤트 추가와 메시지 상태 검사를 직렬화하고 기록을 동기화한다. 잠금 소유자가 죽으면 OS가 잠금을 해제한다. 불완전한 마지막 줄은 보존하고 다음 줄과 분리하며, 개행만 누락된 완전한 기록은 재시도 중복 검사 전에 복구한다. 구버전 프로세스나 잠금을 무시하는 외부 작성자와의 동시 쓰기는 보장하지 않는다. 파일 손상 및 저장 장치의 동기화 보장은 별도 문제다.

outbox는 원본을 별도 이름으로 먼저 인수하고 그 이름을 재시도 키로 사용한다. 중단된 인수 파일은 다음 `post`에서 재시도한다. 다른 프로세스가 인수 중인 파일을 계속 수정하는 경우는 보호하지 못하므로 생산자는 파일 작성 완료 후 `post`를 호출해야 한다.

## 남은 통합

동시 소비자는 `claim`을 사용해야 하며 비파괴 `read`나 `--all`은 인수가 아니다. 외부 CLI 접수에 멱등 키가 없으면 중단 시 결과는 불명으로 두고 자동 재시도하지 않아야 한다. 총괄 깨우기, 질문에 대한 답변 연결 및 프로바이더 접수·확인 기록은 각 실행 경로에서 이 인터페이스를 사용하도록 별도 통합해야 하며, 이 ADR은 exactly-once 처리를 주장하지 않는다.
