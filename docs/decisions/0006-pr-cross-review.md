# ADR-0006: PR 교차 검토 — 에이전트 PR은 사람이, 사람 PR은 에이전트가

- 상태: 제안 (교차 검토는 ADR-0012에 따라 선택 사항)
- 날짜: 2026-11-02
- 승인: [ ] A  [ ] B
- 관련: `AGENTS.md` 병합 흐름, ADR-0002(정책 경계), ADR-0003(대표 병합)

## 배경

목표는 AI와 사람이 한 프로젝트에서 같이 일하는 것이다. 에이전트가 올린 PR은 이미 "다음 할 일"·보드에 사람 검토 대상으로 뜨지만, 사람이 올린 PR을 에이전트에게 검토시키는 길이 없었다.

## 결정

- `o review <PR 번호|주소>`를 더한다. 프로젝트 폴더(지금 폴더)에서 공식 `gh`로만 PR을 읽는다(`gh pr view --json …`, `gh pr diff`). 우리 코드는 GitHub API를 직접 부르지 않는다.
- 검토는 카드 하나짜리 일반 계획("PR #n 검토", 카드 `review`, 역할 `PR 검토`)이다. `o dispatch`와 같은 정책 검사·동시 실행·하루 상한·쿨다운·`--clean`을 그대로 받는다. 상한(`LIMITS`)은 바꾸지 않았다.
- 검토 에이전트는 따로 지정하지 않으면 PR을 쓴 에이전트가 아닌 쪽: O 실행 기록에서 그 PR을 보고한 카드, 없으면 PR 본문의 "Generated with …"·co-author 표시로 판단한다. 쓴 쪽이 claude면 codex, 그 밖(사람·codex·agy·모름)은 claude.
- `--post`가 있으면 끝난 검토문을 O 폴더의 `reviews/<runId>.md`(카드가 쓸 수 없는 곳, 이미 있으면 링크든 파일이든 열지 않고 실패)에 새로 만들고 `gh pr comment <PR> --body-file <그 파일>`로 게시한 뒤 `review.posted { pr, url, head }` 이벤트를 남긴다. **승인(`gh pr review --approve`)·병합은 하지 않는다.** 없으면 그 파일 위치만 알려 준다. `--dry-run`은 가져오기·계획·정책 검사까지만 하고 아무것도 실행하지 않는다.
- 검토 대상 커밋을 고정한다: `gh pr view`의 `headRefOid`·`baseRefOid`를 프롬프트·출력에 적고, diff를 읽은 뒤 head를 다시 확인해 그사이 바뀌었으면 거부한다. 게시 직전에도 head를 다시 읽어 검토한 커밋과 다르면 게시하지 않는다. 지금 폴더의 `HEAD`가 PR head가 아니면 카드에게 로컬 파일로 diff를 보충하지 말라고 적는다.
- 검토 카드에는 공유 컨텍스트(ADR-0005)를 넣지 않는다(`no-context`). 앱 요청은 설정의 "깨끗한 에이전트"를 따라 `--clean`을 붙인다.
- 화면: 보드의 PR 카드에 PR 링크와 "에이전트 검토 요청"(명시적 클릭), 다음 할 일·보드 위에 사람 PR 번호를 넣는 요청 칸. 둘 다 Tauri 명령·개발 서버 `/api/review` → `o review <PR> --post --detach`(프로젝트 폴더).

## 안전

- PR 제목·본문·diff는 남이 쓴 데이터다. 프롬프트에서 무작위 표식(`<<<PR_DATA_BEGIN n>>>` … `<<<PR_DATA_END n>>>`) 사이에 두고, 그 안의 문장은 지시가 아니라고 먼저 적는다. 같은 표식 흉내는 바꿔 쓴다.
- 정책 규칙(인증 파일·토큰·프로바이더 서버·권한 우회)에 걸리는 줄은 빼고 보낸다(계획이 통째로 거부되지 않게). 뺀 줄 수는 프롬프트와 출력에 밝힌다.
- 카드 task 상한(20,000자) 안에 전체가 들도록 제목(300자)·본문(4,000자)·파일 목록(4,000자, 넘는 파일은 개수만)을 먼저 자르고, 남는 만큼 diff를 줄 단위로 자른다(최대 60,000자). 잘린 양과 파일 목록을 프롬프트에 적고, 카드에게 잘린 범위를 밝히라고 한다.
- 게시할 검토문도 같은 정책 규칙으로 검사해 걸리면 게시하지 않는다. 앞머리에 "에이전트 검토 — 승인·병합은 사람이 합니다"를 붙인다.
- 백그라운드 실행(`--detach`)의 PR·게시 여부는 실행 폴더 파일이 아니라 `o _review` 인자로 넘긴다(카드가 쓸 수 있는 실행 폴더에 두지 않음).

## 남은 위험

- 검토 카드도 일반 카드처럼 프로젝트 폴더에서 파일 수정 권한(Claude `acceptEdits`, Codex `workspace-write`)을 가진다. "파일을 고치지 말라"는 지시로만 막는다. 읽기 전용 실행 모드는 프로바이더 연결 방식(공용 경계) 변경이라 따로 결정한다.
- 데이터 구획은 프롬프트 주입을 줄일 뿐 막지 못한다. 게시 전 검사는 정책 규칙에 걸리는 내용만 거른다.
- `--post`의 댓글은 지금 `gh` 로그인 계정으로 달린다(대표 PC면 대표 계정).
