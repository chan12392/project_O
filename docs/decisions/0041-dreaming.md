# ADR-0041: Dreaming — Graph·Wiki·Dreaming을 한 화면의 탭으로 두고, 외부 자료와 작업 기록을 로컬에서 엮는다

- 상태: 채택
- 날짜: 2026-11-10
- 별도 승인 대기 없음 (ADR-0012)
- 관련: [ADR-0033](0033-graph-tab.md)(Graph 탭 — 이 결정이 화면 위치와 그리는 방식을 바꾼다), [ADR-0019](0019-navigation-images-schedules.md)(왼쪽 목록), [ADR-0005](0005-shared-session-context.md)(실행 색인에서 만드는 컨텍스트 — 같은 색인을 읽는다)

## 배경

- 왼쪽 위에 `WIKI`(준비 중이던 빈 화면)와 `Graph`가 따로 있었다.
- 대표 요청: 전부 **Dreaming** 하나로 묶는다. 그 안에 Graph, Wiki, Dreaming 탭을 둔다. Graph는 지금 그대로, Wiki는 옵시디언처럼 왼쪽에 폴더로 나뉜 문서 목록, Dreaming은 Wiki의 문서를 그래프로 엮은 신경망 모양의 3D 화면이다. project_O의 Dreaming은 오라클(서버)이 아니라 **로컬**에서 돈다.
- 대표 요청(같은 날 정정): Dreaming은 프로젝트의 문서를 프로젝트별로 보여 주는 곳이 아니다. **외부 자료와 에이전트의 작업 성공·실패 기록을 넣어 두는 곳**이다. Wiki와 Dreaming은 같은 저장소를 보고, 작업 기록은 자동으로 들어가며, 외부 자료는 글·파일·웹 주소로 넣고, 저장소는 PC 전체에서 하나다.
- 대표 요청: Graph와 Dreaming의 그래프는 은은하게 빛나고, 만들어지는 데 시간이 조금 더 걸리더라도 버벅이지 않아야 한다.
- 이전 Graph 화면이 버벅인 이유: 노드마다 메시(와 후광 스프라이트), 링크마다 선 객체를 따로 만들어 노드 1,500개면 그리기 호출이 수천 번이었다. 배치 계산(힘 시뮬레이션)이 화면 스레드에서 돌았고, 펼쳐지는 동안 0.1초마다 그래프 데이터를 통째로 다시 넘겼다.

## 결정

### 화면 구조

- 왼쪽 위 항목은 **Dreaming** 하나다(`WIKI`·`Graph` 항목은 없앤다). 화면 위에 탭 세 개를 둔다: **Graph | Wiki | Dreaming**.
- Graph 탭은 ADR-0033의 화면 그대로다(범위 목록, 도구 막대, Deep).
- Wiki와 Dreaming은 같은 문서를 본다. Dreaming에서 문서 노드를 고르면 "Wiki에서 열기"로 그 문서가 Wiki 탭에 열린다.
- 설정의 "Wiki" 섹션(준비 중)은 없앤다. 그래프 효과 설정은 설정 → Graph 하나이고 Dreaming 그래프도 그 값을 쓴다.

### Dreaming이 담는 것 — 문서 네 종류, PC 전체에서 하나

| 폴더 | 무엇 | 어디에 있나 |
|---|---|---|
| `배운 것/<프로젝트>/<실행>-<카드>-<n>.md` | 카드가 일하다 남긴 메모 하나 | 따로 저장하지 않는다. 실행 기록의 팀 메시지(`msg`, 받는 사람 `wiki`)를 문서로 보여 준다 |
| `외부 자료/<파일>.md` | 사람이 넣은 자료: 붙여 넣은 글, 글자로 된 파일의 내용, 웹 주소의 글 | `<O 상태 폴더>/dreaming/external/` 아래 파일 하나씩 |
| `작업 성공/<프로젝트>/<실행>-<카드>.md` | 성공으로 끝난 카드 하나 | 따로 저장하지 않는다. 실행 색인(`o.db`)에서 읽어 문서로 보여 준다 |
| `작업 실패/<프로젝트>/<실행>-<카드>.md` | 실패로 끝난 카드 하나 | 위와 같다 |
| `도구 오류/<프로젝트>/<실행>-<카드>.md` | 도구 호출이 실패하거나 거절된 카드 하나(헛된 호출 모음) | 위와 같다 |

- **작업 기록은 자동이다.** 카드가 `done`이나 `failed`로 끝나면(`card.end`) 다음에 열 때 문서로 보인다. 사람이 멈춘 카드(`stopped`)는 넣지 않는다. 실행 폴더를 지우면 그 기록도 사라진다. 같은 실행을 다시 시작하면(`run.start`) 그 뒤의 끝만 센다(색인과 같은 규칙). 최근 2,000개까지 보여 준다.
- 기록 문서의 내용: 결과(성공 / 실패와 종료 코드), 프로젝트, 끝난 시각, 실행·카드 ID, 맡긴 일(`plan.json`의 `task`), 결과 글, 바뀐 파일(편집 도구가 댄 경로 — ADR-0005와 같은 규칙). 결과 글 없이 실패한 카드는 마지막 메시지 세 개를 붙인다.
- **배운 것은 카드(LLM)가 남긴다.** 팀 메시지의 받는 사람에 `wiki`가 더해진다. 카드가 `o msg send --to wiki "제목
내용"`(outbox를 쓰는 CLI는 `to: wiki`)으로 보내면 그 메시지가 메모 문서가 된다. 첫 줄이 제목이다.
  - 새 권한을 열지 않는다. 카드에 이미 열린 `o msg`와 그 정책 검사(로그인 정보·프로바이더 서버·권한 우회 규칙, 글자 수 상한)를 그대로 거치고, 자기 실행의 기록에만 쓴다.
  - `wiki`는 받는 사람으로만 쓸 수 있고 카드 ID로는 쓸 수 없다(예약어). 아무의 받은 편지함도 아니라 다른 카드나 총괄에게 전달되지 않는다. 답할 사람이 없으므로 질문·답장은 거부하고, 보낸 카드가 `o msg cancel`로 거둔 메모는 문서로 만들지 않는다. 다른 팀 메시지처럼 ADR-0005의 색인에는 들어가 `o context` 검색에 나온다.
  - 카드 프롬프트에 한 줄이 더해진다: 다음 작업에도 쓸 사실·함정·해결법을 `wiki`에게 남기라는 안내.
  - 문서 본문은 메모 글뿐이다. 남긴 카드·프로젝트·시각은 문서의 필드로 따로 두어, 읽는 쪽(LLM)이 본문만 받게 한다. 메모는 뺄 수 없다(실행 기록이다). 최근 5,000개까지 보여 준다.
- **도구 오류도 자동이다.** 카드의 도구 호출이 실패하거나 거절되면 실행 기록에 새 이벤트 `card.tool.error`(`cardId`·`name`·`summary`·`error`)가 남고, 그런 호출이 하나라도 있는 카드가 문서 하나가 된다. 카드가 어떻게 끝났는지는 따지지 않는다(성공한 카드, 사람이 멈춘 카드, 아직 도는 카드도 포함). 최근 2,000개까지 보여 준다.
  - 무엇을 실패로 보나: Claude는 오류로 표시된 도구 결과(`tool_result`의 `is_error`), Codex는 0이 아닌 종료 코드·`failed`·거절된 명령과 적용되지 않았거나 거절된 파일 변경, 실패한 MCP 호출(단, 출력 없이 종료 코드 1로 끝난 명령은 "찾지 못함·거짓"이라는 답이라 실패로 보지 않는다 — `rg`·`grep`·`git diff --quiet` 등), OpenCode는 `error` 상태의 도구 호출, Devin은 거절된 도구 호출. Antigravity는 보류 중이라 읽지 않는다.
  - `error`는 한 줄 300자까지다(Codex는 출력의 마지막 네 줄). 호출 자체는 지금처럼 `card.tool`로도 남는다.
  - 문서의 내용: 프로젝트, 마지막 실패 시각, 실행·카드 ID, 실패한 호출 수, 호출별 도구 이름·요약·마지막 오류 글과 되풀이한 횟수(많이 되풀이한 것부터, 카드마다 서로 다른 호출 200개까지).
  - 총괄의 도구 오류는 모으지 않는다. 이 이벤트가 생기기 전의 실행에는 도구 오류 문서가 없다(지난 기록을 다시 읽어 만들지 않는다).
  - 실패 없이 같은 호출을 되풀이한 것은 헛된 호출인지 가릴 규칙이 없어 모으지 않는다.
- 같은 이름의 프로젝트 폴더가 둘이면 두 번째부터 `이름 (2)`로 나눈다(먼저 기록된 쪽이 이름을 지킨다).
- **외부 자료는 사람이 넣는다.** 형태는 셋이다.
  - 글: 제목과 내용(Markdown).
  - 파일: 글자로 된 파일. 앱 창이 파일을 읽어 **내용과 파일 이름만** 보낸다(파일 위치는 보내지 않는다).
  - 웹 주소: O가 그 주소를 한 번 읽어 글로 바꿔 저장한다. 나중에 페이지가 바뀌어도 따라 바뀌지 않는다.
- 자료 하나는 1 MiB까지, 2,000개까지다. 관련 프로젝트를 하나 붙일 수 있다. 자료는 뺄 수 있다(파일 삭제). 작업 기록은 뺄 수 없다.
- 자료 파일은 머리말(`<!-- o-dream` … `-->`: `title`·`source`·`project`·`added`) 뒤에 본문이 온다. 머리말이 없는 `.md` 파일을 그 폴더에 직접 두어도 읽는다(제목은 첫 `# ` 줄이나 파일 이름).
- LLM을 부르지 않고 요약하지 않는다. 기록을 정리·요약한 교훈 문서를 만드는 일은 다음 단계다.

### 개정 1 — Wiki는 모으고, Dreaming은 O의 동작을 고친다

- 역할을 나눈다. **Wiki**는 모은 것(카드가 남긴 메모, 자동 기록, 사람이 넣은 자료)이고, **Dreaming**은 그것을 근거로 하네스를 조금씩 고치는 일이다.
- 근거에 따라 고치는 곳이 다르다.
  - 도구 오류와 작업 성공·실패 기록 → **O CLI의 동작**(O가 카드에 주는 프롬프트). 이번에 만든다.
  - 외부 자료 → 사용자의 하네스(전역 지시·스킬). **보류한다.** 외부 글은 O가 출처를 믿을 수 없어서, 고치는 범위와 승인 방식을 따로 정한 뒤에 한다. 지금은 Wiki에 보이기만 한다.
- 지금 고치는 것은 하나다: **그 프로젝트의 카드 프롬프트에 더하는 "반복 실패" 줄**(`o-core`의 `tuning`). 에이전트 CLI의 설정(`~/.claude`, `~/.codex` 등), 프로젝트 파일, 권한·허용 명령, 프로바이더·모델 기본값은 건드리지 않는다.
- 규칙(LLM 없음, 최근 30일의 실행만 본다):
  - `tool-failure`: 같은 프로젝트에서 같은 도구 호출(이름과 요약)이 카드 둘 이상에서, 또는 세 번 이상 실패했다.
  - `card-failure`: 같은 프로젝트에서 결과 글의 첫 줄이 같은 실패가 두 실행 이상에서 나왔다. 실제로 시작해서 스스로 실패한 카드만 센다: O가 시작하지 않은 카드(선행 작업 실패, 예산 초과)와 사용량 한도에 걸린 카드는 세지 않는다.
- **자동으로 적용한다.** 실행이 시작할 때 실행 기록을 한 번 다시 읽어, 해당하는 줄을 최신 실패부터 5개까지(줄마다 200자) 과제 뒤에 붙인다. 머리말에 참고 자료이며 지시나 권한이 아니라고 적는다. O 가드의 코드 규칙에 걸리는 줄은 만들지 않는다.
- **나중에 확인하고 되돌린다.** 바꾼 것은 `<O 상태 폴더>/dreaming/tuning.json`에 남는다(프로젝트, 줄, 횟수, 처음·마지막 시각, 근거가 된 실행·카드 5곳까지, 상태). 상태는 `applied`·`reverted`·`expired`다.
  - 사람이 되돌린 것은 같은 실패가 또 나와도 다시 적용하지 않는다. 다시 적용도 사람이 한다.
  - 이 파일은 실행마다의 프로세스·앱·`o dream`이 함께 읽고 쓴다. 읽어서 다시 쓰는 동안 `dreaming/tuning.lock` 파일 잠금을 잡아, 되돌린 것이 먼저 읽은 쪽의 쓰기에 덮이지 않게 한다. 읽을 수 없게 된 파일은 덮어쓰지 않고 `tuning.bad.json`으로 옮겨 둔다.
  - 30일 동안 다시 나오지 않은 것은 스스로 끝난다(`expired`). 다시 나오면 다시 적용된다.
  - 명령: `o dream changes [--json]`, `o dream revert <ID>`, `o dream restore <ID>`. 되돌리기·다시 적용은 카드와 에이전트 환경에서 거부한다. 화면은 Dreaming 탭의 "바꾼 것".
- 한계: 줄의 내용은 도구가 낸 오류 글과 카드의 결과 글에서 온다. 한 줄로 줄이고 가드 규칙을 거치지만, 그 글이 카드에게 지시처럼 읽히는 것을 완전히 막지는 못한다(ADR-0005의 컨텍스트와 같은 한계). 프로젝트와 무관한 실패(네트워크 오류 등)도 되풀이되면 줄이 된다 — 되돌리면 된다. 실패한 호출만 보므로 "실패 없이 헛돈" 호출은 잡지 못한다.
- ADR-0005는 실패 결과를 카드에 넣지 않는다. 이 개정은 그 규칙을 바꾸지 않고 따로 선다: 넣는 것은 실패 결과 전체가 아니라 **되풀이된** 실패의 한 줄이다.

### 개정 2 — 태그로 찾고, 필요한 문서만 읽는다

- 대표 요청: Wiki 문서를 전부 읽지 않는다. 태그를 걸어 두고 특정 문서만 읽게 한다.
- **태그.** 문서마다 태그가 붙는다(소문자, `#` 없이 저장, 문서마다 12개까지).
  - 메모(배운 것): 카드가 메모 글에 쓴 `#태그`. 그 카드의 작업 기록과 도구 오류 문서도 같은 태그를 받는다.
  - 외부 자료: 넣을 때 적은 태그(머리말 `tags:`)와 본문의 `#태그`.
  - 태그로 보지 않는 것: 숫자만 있는 것(`#12`), 색 값(`#ffcc00`), 코드 구획 안의 글, 글자·숫자·`-`·`_` 밖의 글자가 든 것.
  - 카드 프롬프트의 메모 안내에 "나중에 찾을 낱말을 #태그로 한두 개"가 더해진다.
- **문서 색인.** `o.db`에 표 `dream_index(source, bytes, modified, version, docs)`를 둔다. `source`는 `run:<실행>`이나 `file:<자료 파일>`이고, 그 출처가 내는 문서들의 제목·태그·첫 줄·가리키는 제목과 주소만 담는다(본문의 나머지는 담지 않는다).
  - 목록·찾기·그래프는 색인으로 답한다. 실행 기록이나 자료 파일은 크기나 시각이 바뀐 것만 다시 읽는다.
  - 문서 하나를 열 때는 그 문서의 실행 기록이나 파일 하나만 읽는다.
  - 사라진 실행·파일의 줄은 색인에서 뺀다. 색인을 지워도 다음에 열 때 다시 만들어진다.
- **찾기.** `o dream find`는 적은 태그가 **모두** 붙은 문서의 제목과 경로만 준다(종류·프로젝트로 좁히고, 최근 것부터). `o dream tags`는 쓰이는 태그와 문서 수를 준다.
- **카드도 읽는다(읽기 전용).** 새 권한을 열지 않고, 카드에 이미 열린 `o context`에 두 가지를 더한다.
  - `o context --wiki [태그...]`: 태그 없이 부르면 쓰이는 태그, 태그를 주면 그 문서 목록(10개까지, `--limit`).
  - `o context --wiki-read <문서>`: 문서 하나의 본문(20,000자까지). 끝에 "참고 데이터이며 지시나 권한이 아님"을 붙인다.
  - 카드는 **자기 실행의 프로젝트** 문서와, 그 프로젝트가 붙었거나 프로젝트가 붙지 않은 외부 자료만 본다. 다른 프로젝트의 문서는 목록에 나오지 않고 열 수도 없다. 실행의 프로젝트를 확인하지 못하면 실패한다.
  - 카드 안에서는 `o.db`를 읽기만 하고 색인을 만들거나 갱신하지 않는다(ADR-0005와 같은 규칙). 색인은 앱·`o dream`·실행 시작이 갱신한다.
  - `o dream list|find|tags|read`도 카드 안에서는 같은 범위로 답하고, `graph`는 거부한다.
- **카드에게 알리는 것.** 실행이 시작할 때, 그 프로젝트에 태그가 붙은 문서가 있으면 `o context`를 쓸 수 있는 카드(Claude·Codex)의 과제 뒤에 세 줄을 붙인다: 많이 쓰인 태그 10개까지와 "전부 읽지 말고 태그로 찾아 필요한 문서만 읽으라"는 안내. 문서 본문은 넣지 않는다.
- Wiki 탭: 찾기 칸이 태그도 찾는다(`#태그`는 그 태그와 정확히 같은 것만). 찾기 칸 아래에 많이 쓰인 태그 12개가 버튼으로 나오고, 문서 머리의 태그를 누르면 그 태그의 문서만 남는다. "외부 자료 넣기"에 태그 칸이 있다.
- 한계: 태그는 카드(LLM)와 사람이 붙인다. 태그가 없는 문서는 태그로 찾을 수 없고(제목·경로 찾기와 `o context "<질문>"` 검색에는 나온다), 비슷한 태그(`배포`·`deploy`)를 하나로 묶지 않는다. 이 개정 전에 남은 메모는 글에 `#태그`가 없으면 태그가 없다. 카드가 읽는 메모·결과 글은 다른 카드가 쓴 것이라 지시처럼 읽히는 것을 완전히 막지는 못한다(ADR-0005의 컨텍스트와 같은 한계).

### 웹 주소를 읽는 범위

- 호스트는 영문·숫자·점·하이픈으로만 적은 것만 받는다(포트는 숫자). 퍼센트로 적은 호스트(`%31%32%37.0.0.1`)나 전각 숫자처럼 읽는 쪽(curl)이 풀어서 다른 주소로 읽는 표기를 막기 위해서다. 한글 도메인은 `xn--` 표기로 넣는다. 경로·질의의 퍼센트 표기는 그대로 받는다.
- `http://`·`https://`만 받는다. 로그인 정보가 든 주소(`user@`), 이 PC와 내부 네트워크 주소(`localhost`, `.local`·`.internal`, 점 없는 이름, 사설·루프백·링크 로컬 IP와 그 다른 표기 — `127.1`, `0x7f.0.0.1`, 정수 하나, IPv4를 담은 IPv6, `localhost.`)는 거부한다. curl의 목록 문법(`{a,b}`)이 든 주소도 거부한다.
- 프로바이더 서버 직접 호출 규칙(`o-guard`의 코드 규칙)에 걸리는 주소는 거부한다.
- 시스템의 `curl`로 요청한다(창 없음, 사용자의 curl 설정 파일은 읽지 않음, http(s)만, 요청마다 20초, 5 MB까지). 리디렉션은 curl이 따라가지 않고 O가 5번까지 한 걸음씩 따라가며, 넘겨 보내는 주소마다 위 규칙을 다시 적용한다. HTML이면 스크립트·스타일을 버리고 글과 제목만 남긴다. 글이 아닌 응답(그림·PDF)은 넣지 않는다.
- 한계: 이름이 내부 주소로 풀리는 호스트는 막지 못한다. UTF-8이 아닌 페이지는 글자가 깨질 수 있다.

### 문서를 잇는 것 (로컬 규칙)

- 같은 실행의 카드: 끝난 순서대로 뒤 카드 → 앞 카드.
- 후속 실행(`run.followup`): 후속 실행의 카드 → 원래 카드.
- 같은 프로젝트에서 같은 파일을 바꾼 기록: 뒤 기록 → 바로 앞 기록(기록마다 파일 40개까지).
- 메모 → 그 메모를 남긴 카드의 작업 기록(있을 때).
- 도구 오류 문서 → 그 카드의 작업 기록(있을 때).
- 같은 프로젝트에서 같은 호출(도구 이름과 요약이 같음)이 실패한 도구 오류 문서: 뒤 문서 → 바로 앞 문서(문서마다 호출 40개까지, 요약이 빈 호출은 빼고).
- 글이 가리키는 것: 본문에 적힌 웹 주소가 어떤 외부 자료의 출처와 같으면 그 자료로, `[[제목]]`이 어떤 문서의 제목과 같으면 그 문서로.
- 그래프에서만: 관련 프로젝트가 붙은 외부 자료 → 그 프로젝트의 `작업 성공`·`작업 실패`·`도구 오류` 묶음.
- 뜻이 비슷한 문서를 이어 주지는 않는다.

### Wiki 탭

- 왼쪽: "외부 자료 넣기", 새로고침, 문서 찾기(제목·경로·프로젝트·태그 — 개정 2), 폴더 트리(접고 펼침, 폴더마다 문서 수). 맨 위 폴더는 `외부 자료` → `작업 성공` → `작업 실패` → `도구 오류` 순서이고, 문서는 제목으로 보이며 최근 것이 위다.
- 오른쪽: 종류·시각·프로젝트·출처, 본문(GitHub 방식 Markdown), "이 문서가 이어진 문서", "이 문서로 이어진 문서". 외부 자료에는 "자료 빼기"(두 번 눌러 확인)가 있다.
- 본문의 링크: 목록의 문서 경로면 Wiki 안에서 열고, http(s)면 바깥 브라우저로 연다. 그 밖의 링크는 글자로만 둔다. 이미지는 불러오지 않는다. 원본 HTML은 글자로 남는다.

### Dreaming 탭

- 노드: `Dreaming` → 묶음(`외부 자료`·`작업 성공`·`작업 실패`·`도구 오류`) → 프로젝트 → 문서. 간선은 위의 "문서를 잇는 것"이다.
- 색은 맨 위 묶음을 따른다(자료·성공·실패가 한 색씩). 문서 노드의 크기는 자신에게 이어진 연결 수를 따른다.
- 빛나는 곳: 지난 24시간 안에 끝났거나 넣은 문서가 `active`, 그 문서가 이어진 문서가 `path`다.
- 노드 상한은 Graph 설정의 `maxNodes`를 쓴다. 빛나는 문서는 항상 남기고 나머지는 최근 것부터 남긴다.

### CLI (`o dream`)

```
o dream list [--json]            문서 목록 { docs: [{ path, title, kind, project?, at, size, tags? }], truncated }
o dream find [--tag <태그>]... [--kind <종류>] [--project <폴더>] [--limit <n>] [--json]
                                 태그가 모두 붙은 문서 목록 (list와 같은 모양, 개정 2)
o dream tags [--project <폴더>] [--json]   쓰이는 태그 [{ tag, count }]
o dream read <문서> [--json]      문서 { path, title, kind, project?, at, tags?, source?, text, truncated, links, backlinks }
o dream graph [--json]           그래프 { nodes, links, truncated }
o dream add -                    외부 자료 넣기. stdin JSON { kind: "text" | "url", title?, text?, source?, url?, project?, tags? }
o dream remove <문서>             외부 자료 빼기
```

- `kind`는 `external`·`done`·`failed`·`tool`·`note`다. `nodes`·`links`는 ADR-0033의 `GraphNode`·`GraphLink`와 같은 모양이다(id `dream`·`d:<폴더>`·`f:<문서>`, 간선 `contains`·`references`).
- `read`·`remove`는 `list`에 나온 문서만 받는다.
- **카드 안(`O_CARD_ID`)에서는 `add`·`remove`를 거부한다.** 카드가 사람이 넣은 것처럼 보이는 자료를 심지 못하게 하기 위해서다(`o context add`와 같은 이유). 카드 CLI에 `o dream`을 열어 주지 않는다. 카드는 `o context --wiki`·`--wiki-read`로 자기 프로젝트의 문서만 읽는다(개정 2).
- 화면은 Tauri 명령 `dream_list`·`dream_read`·`dream_graph`·`dream_add`·`dream_remove`만 부르고, 개발 서버 `/api/dream/list|read|graph|add|remove`는 같은 `o dream` 명령을 쓴다.

### 그래프 그리기 (Graph·Dreaming 공통)

- **배치는 먼저, 화면 밖에서 끝낸다.** 힘 배치(`d3-force-3d`, 이전과 같은 힘에 약한 중심 당김 추가)를 Web Worker에서 끝까지 계산한 뒤 좌표만 화면에 넘긴다. 계산하는 동안 화면은 멈추지 않고, 0.25초 넘게 걸리면 "그래프를 배치하는 중…"을 보여 준다. Worker를 쓸 수 없으면 같은 계산을 화면 스레드에서 한다.
- **묶어서 그린다.** 노드 전체가 구 메시 하나의 인스턴스, 링크 전체가 선 버퍼 하나, 빛 전체가 점 구름 하나, 흐르는 점이 점 구름 하나다. 노드 수와 상관없이 그리기 호출은 네 번이다.
- `3d-force-graph`는 캔버스·카메라·마우스 조작만 맡는다(그래프 데이터는 넘기지 않는다). 노드 고르기와 이름표는 노드 구에 대해서만 직접 계산한다.
- **펼쳐지는 등장**은 유지한다. 좌표가 이미 정해져 있으므로 노드가 부모 자리에서 제자리로 자라는 움직임만 남는다(단계마다 최대 0.26초 간격, 전체 약 1.8초). 끝나면 빛남과 흐름이 켜진다. 같은 범위를 새로고침하면 노드와 링크 구성이 같을 때 배치를 다시 하지 않고, 바뀌었으면 있던 노드는 제자리 근처에서 0.6초 동안 옮겨 간다.
- **은은한 빛.** 효과가 켜져 있으면 모든 노드가 옅은 빛을 두른다(어두운 테마는 빛을 더하고, 밝은 테마는 옅게 덮는다). 빛나는 노드는 더 넓고 밝게 빛난다. 동작 줄이기가 꺼져 있으면 빛이 천천히 숨 쉰다. 효과를 끄면 빛이 없다.
- 전체 그래프의 조각(`o graph part`)이 도착할 때마다 배치를 다시 하지 않도록 0.18초 동안 모아 한 번에 계산한다.

## 영향과 한계

- ADR-0033의 화면 위치("왼쪽 위 Graph 카테고리")와 "Wiki 섹션은 준비 중으로 둔다"는 이 결정으로 바뀐다. `o graph`의 명령과 데이터는 그대로다.
- 새 저장 위치: `<O 상태 폴더>/dreaming/external/`. 상태 폴더는 에이전트가 건드리지 못하는 곳이라(가드) 자료는 사람과 `o dream`만 바꾼다. 계정 정보는 두지 않는다.
- 앱이 처음으로 사람이 준 임의의 웹 주소에 요청을 보낸다(위 "웹 주소를 읽는 범위").
- `d3-force-3d`(MIT)를 앱의 직접 의존성으로 적는다. 이전에도 `3d-force-graph`를 통해 번들되던 같은 버전이다.
- 작업 기록의 결과 글은 카드가 쓴 것이다. 다른 카드의 프롬프트에 넣지 않는다(카드 주입은 ADR-0005의 컨텍스트가 그대로 맡고, 거기에는 실패 결과가 들어가지 않는다). 개정 2부터 카드가 태그로 찾아 **스스로 여는** 것은 된다(같은 프로젝트의 문서만, 프롬프트에는 태그 이름만).
- 이벤트 계약에 `card.tool.error`가 더해진다. 이 이벤트를 모르는 이전 빌드는 그 줄을 건너뛴다. 카드 화면의 기록에는 "〈도구〉 실패: 〈오류〉" 한 줄로 보이고, 총괄에게 주는 실행 요약에서는 `card.tool`처럼 뺀다. 오류 글은 도구가 낸 출력이라 카드 메시지와 같은 수준으로 다룬다(이 PC의 실행 기록에만 남는다).
- 개정 2 전에는 문서를 열 때마다 모든 실행 기록을 다시 읽었다. 지금은 `dream_index`로 답하고 바뀐 출처만 다시 읽는다(위 개정 2). 색인을 처음 만들 때 한 번은 전부 읽는다.
- 카드의 분리 워크트리 경로로 바뀐 파일은 적힌 경로 그대로 비교한다. 같은 파일이 다른 경로로 적히면 이어지지 않는다.
