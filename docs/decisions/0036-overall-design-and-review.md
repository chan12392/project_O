# ADR-0036: 전체 총괄의 설계와 프로젝트 계획 검토·승인

- 상태: 채택
- 날짜: 2026-11-09
- 별도 승인 대기 없음 (ADR-0012)
- 관련: [ADR-0032](0032-overall-lead.md)(전체 총괄 — 이 ADR이 "전달은 자동", "사람이 하는 결정은 지금과 같다"를 바꾼다), [ADR-0018](0018-lead-work-graph.md)(설계 패널), [ADR-0014](0014-yolo-mode.md)(YOLO 자동 실행 한도), [ADR-0034](0034-lead-tabs.md)(총괄 탭)

## 배경

- 지금 전체 총괄은 `o-design`을 쓰면 거부되고, `o-forward`는 턴이 끝나면 사람 확인 없이 프로젝트 총괄에게 넘어간다. 프로젝트 총괄의 계획은 사람이 프로젝트마다 "실행"을 눌러야 돈다.
- 대표 요청: 전체 총괄도 오른쪽 패널의 설계로 먼저 정리하고, 사람은 그 설계를 확인해 넘긴다. 그 뒤 프로젝트 총괄의 설계는 전체 총괄이 검토해 승인하고, 승인하면 바로 실행한다. 사람은 가장 중요한 결정(전체 설계)만 한다.

## 결정

```
사람 ──▶ 전체 총괄 ── o-design·o-forward ──▶ 오른쪽 패널(설계 + 넘길 요청)
                                              │ 사람 "요청 전달"
                                              ▼
                                       프로젝트 총괄 ── o-plan ──▶ 전체 총괄 검토(o-review)
                                              ▲                        │ approve: 바로 실행(정책·자동 실행 한도)
                                              └──── revise: 보완 요청 ──┘ (2번까지)
```

### 전체 설계와 요청 전달

- 전체 총괄은 `o-design`(프로젝트 총괄과 같은 형식: 목표·결정·미결정)을 쓸 수 있다. `lead.design`으로 남고 오른쪽 패널 "설계"에 보인다. 다음 턴의 프롬프트에 마지막 설계가 들어간다.
- `o-forward`는 바로 넘기지 않는다. 지금과 같은 검사(`overall::check`: 목록의 프로젝트, 한 턴 3개, 프로젝트마다 하나, 글 길이)를 통과하면 `lead.forward-plan { proposalId: "<대화>-f<n>", items, provider, model?, effort?, profile }`으로 저장한다. YOLO가 켜져 있어도 자동으로 넘기지 않는다.
- 사람이 패널의 **요청 전달**(`o lead forward <proposalId>`, Tauri `lead_forward`, 개발 서버 `/api/lead/forward`)을 누르면:
  - 계획 분배와 같은 순서로 잠근다(`current.lock` → 대화 턴 → `dispatch.lock`). 대화가 열려 있고, 답하는 중이 아니고, 그 제안이 대화의 마지막 말(뒤에 사람 글·새 제안이 없음)이어야 한다.
  - 한 제안은 한 번만(`leads/<대화>/forward-plans/<proposalId>`를 `create_new`).
  - 목록 검사를 다시 하고 항목마다 `lead.forward { proposal }`을 남긴 뒤 지금처럼 `o _lead-forward`를 띄운다.
- `o lead forward`는 사람 전용이다. 에이전트 환경(`O_AGENT_ROLE`·`O_CARD_ID`)에서는 거부하고, 에이전트 훅(`AGENT_DISPATCH`)도 막는다.

### 프로젝트 계획 검토

- 사람이 전달한 요청(`proposal`이 있는 `lead.forward`)으로 프로젝트 총괄이 정책을 통과한 계획(`lead.plan`, `ok`)을 내면, 같은 `o _lead-forward` 프로세스가 원본 전체 총괄 대화에서 **검토 턴**을 돈다.
  - 전체 총괄이 답하는 중이면 끝날 때까지 기다린다(최대 총괄 턴 시간 15분). 그 사이 원본 대화가 닫히거나 중지되면 검토하지 않는다.
  - 검토 턴의 `lead.user`는 O가 쓴 짧은 글이고 `origin: "review"`다. 넘긴 요청, 프로젝트 총괄의 최신 설계, 계획(카드)은 프롬프트에 "신뢰할 수 없는 참고 데이터"로 들어간다.
  - 전체 총괄의 에이전트·모델·노력·프로필은 그 전달과 같다. 검토 턴은 읽기 전용이다.
- 답에는 ```` ```o-review ```` 블록 하나: `{"verdict":"approve"|"revise","notes":"검토 의견"}`. 어느 계획을 보는지는 O가 정한다(블록에 계획 id가 없다).
  - 블록이 없거나, 형식이 틀리거나, 다른 블록(`o-forward`·`o-design`·`o-plan`·`o-followup`·`o-ask`)이 섞이면 승인하지 않는다. 계획은 사람의 "실행"을 기다린다.
  - 검토 턴이 아닌 턴의 `o-review`는 오류다.
- 결과는 `lead.review { planId, project, verdict, notes }`로 전체 대화와 프로젝트 대화에 모두 남는다. 화면은 계획 카드에 "전체 총괄 승인"·"보완 요청"을 보인다.

### 승인하면 바로 실행

- `approve`면 O가 그 계획을 분배한다. 사람의 "실행"과 같은 경로다: 같은 잠금, 프로젝트 대화가 열려 있고 그 계획이 대화의 최신 계획인지, 정책 재검사, 한 번만 실행, 격리 작업 폴더.
- 그 위에 YOLO 자동 실행 한도(ADR-0014)를 그대로 건다: 하루 사용 예산이 켜져 있어야 하고, 카드 수·이 대화의 실행 중인 실행·한 시간 횟수·같은 계획 반복 한도. `lead.autorun`으로 기록해 YOLO 자동 실행과 횟수를 함께 센다. 한도에 걸리면 사유를 계획 카드에 보이고 사람의 "실행"을 기다린다.
- YOLO가 꺼져 있어도 승인한 계획은 실행한다. 이것이 이번 결정의 요점이다. 카드는 지금 YOLO 설정(`o yolo`)과 전달한 프로필로 돈다(앱의 "실행"과 같은 기준).
- 프로젝트 대화가 그 사이 바뀌었거나(사람의 새 글, 새 계획) 원본 전체 대화가 중지·닫혔으면 실행하지 않는다.

### 보완 요청

- `revise`면 `notes`를 같은 프로젝트 총괄에게 다시 넘긴다: 전체 대화에 `lead.forward { proposal, revision: <계획 id> }`를 남기고 `o _lead-forward`. 새 계획은 다시 검토한다.
- 한 제안·한 프로젝트에 보완 요청은 2번까지다(`overall::MAX_REVISIONS`). 넘으면 더 넘기지 않고 계획은 사람의 "실행"을 기다린다.

## 이유

- 사람이 확인할 곳을 하나로 모은다. 전체 설계와 넘길 요청을 한 화면에서 보고 한 번 누르면, 그 범위 안의 프로젝트 계획은 전체 총괄이 설계와 맞는지 보고 진행한다.
- 승인으로 실행되는 범위는 사람이 전달한 요청에서 나온 계획뿐이다. 승인할 계획은 코드가 정하고, 모델은 승인·보완만 고른다.
- 실행 쪽 안전장치는 새로 만들지 않고 이미 있는 것(정책 검사, 자동 실행 한도, 하루 예산, 격리 작업 폴더, 중지)을 그대로 쓴다.

## 영향과 한계

- ADR-0032의 "요청 전달 자체는 사람 승인 없이 자동"은 "사람이 요청 전달을 누른다"로, "사람이 하는 결정은 지금과 같다"는 "사람은 전체 설계와 넘길 요청을 승인하고, 그 요청에서 나온 계획은 전체 총괄의 승인으로 실행된다"로 바뀐다.
- 모델이 모델의 계획을 승인한다. 프로젝트 파일에 섞인 지시가 프로젝트 총괄의 계획과 전체 총괄의 검토를 거쳐 실행까지 갈 수 있다. 막는 것은 정책 검사·자동 실행 한도·하루 예산·격리 작업 폴더이고, 사람은 전달 전에 넘길 요청을 본다. 카드는 원본 프로젝트에 자동으로 합치지 않는다(ADR-0018).
- 프로젝트 총괄이 질문(`o-ask`)으로 답하면 검토하지 않는다. 사람이 답한 뒤의 계획은 사람이 실행한다.
- 이전 빌드가 남긴 `lead.forward`(proposal 없음)는 이미 넘긴 요청이다. 검토하지 않는다.
- 새 이벤트 `lead.forward-plan`, `lead.review`와 `lead.forward`의 선택 필드 `proposal`·`revision`, `lead.user`의 `origin: "review"`. 예전 빌드는 모르는 줄을 건너뛴다.
