# ADR-0046: 보안 감사 후 실행·검사 경계 보완

- 상태: 채택 (아래 미해결 경계는 보장하지 않음)
- 날짜: 2026-11-12
- 관련: ADR-0008, ADR-0017, ADR-0035, ADR-0043

## 배경

6개 감사 보고서를 현재 코드와 대조했다. 명령 이름·경로 표기·프로젝트 설정·검사기 출처에 실제 공백이 있었다. 한편 동일 OS 사용자로 실행되는 에이전트와 앱 사이에는 파일 권한으로 강제되는 격리가 없다. 문자열 검사나 변경 가능한 파일에 저장한 해시를 보강하는 것으로 후자를 해결했다고 표현하지 않는다. 각 발견의 판정은 [조치표](../../security-audit/remediation.md)에 남긴다.

## 결정

1. Claude 카드는 인증 방식과 관계없이 프로젝트 설정을 제외하고 O 가드를 실행 설정으로 받는다. 프로젝트 MCP도 읽지 않는다. 평소 프로필을 선택했을 때의 사용자 설정은 계속 신뢰한다. Codex 기본 모드는 훅을 끄고, 프로젝트/상위 프로젝트의 `.codex/config.toml`에서 빈 내용과 협업 관련 불리언 3개(`include_collaboration_mode_instructions`, `[agents]`의 `enabled`, `[features]`의 `multi_agent`)만 허용한다. 다른 키·값·구문과 링크는 CLI 시작 전에 거부한다. 일반 TOML을 임의로 해석하지 않는 제한된 허용 구문이며 MCP·실행·네트워크 설정은 허용하지 않는다. 훅 파일만 있는 저장소도 허용한다. Git 루트와 사용자 홈에서 상위 검색을 멈춘다. 시작 검사와 CLI의 실제 읽기 사이의 파일 변경까지 막는 격리는 아니다. YOLO의 의도된 권한은 유지한다.
2. 가드는 인용·셸 이스케이프를 보수적으로 풀어 검사하고 `command`/`cmd`가 있는 새 셸 도구에도 같은 검사를 적용한다. 알 수 없는 git/gh 별칭·외부 명령, git의 push 경로 설정 변경·환경 설정 주입, 명시적 목적지 없는 push, 고정 규칙 밖 원격 브랜치를 거부한다. 직접 저장소 보호·ref·내용·워크플로를 바꾸는 REST 요청과 GraphQL mutation/불투명 본문은 거부한다. 병합은 검사 가능한 PR 명령 또는 REST PR 병합 경로를 쓴다. 일반 셸·스크립트의 의미를 완전히 판정하는 보안 경계는 아니다.
3. 훅도 Windows 작업 개체로 에이전트 여부를 전달받는다. 사람 전용 CLI 게이트에 거울 동기화, 대화 생성·첨부, 전체 실행·이벤트 조회를 추가한다. 카드는 승인 서버를 시작하지 못한다. 정상 Claude 총괄의 승인 서버는 총괄의 자식이므로 일괄 차단하지 않고, 실제 살아 있는 턴의 식별자·토큰·프로젝트를 확인한다. 이미 존재하는 결정 파일과 링크된 결정 파일은 받지 않는다. 총괄의 카드 사칭은 인자 파싱이 끝난 공통 팀 채널 경계에서 막는다.
4. 상태 경로는 verbatim/UNC 표기를 정리하고 존재하는 상위 경로를 실제 경로로 확인한다. 인덱스는 유효한 실행 ID와 일반 디렉터리만 받고 링크·junction·hardlink 이벤트를 읽지 않는다. 디렉터리가 검사 후 바뀌는 동일 사용자 경합이나 이벤트 내용 자체의 인증까지 해결하지는 않는다. 팀 메시지는 저장 원문을 유지하고 터미널 표시에서 제어 문자를 치환한다.
5. 가드의 Git/GitHub 조회, 거울의 Git, 업데이터의 GitHub CLI는 PATH 대신 표준 설치 위치에서 실행 파일을 찾는다. Windows는 Program Files의 Git/GitHub CLI와 사용자 Programs 설치를, Unix는 `/usr/bin`, `/usr/local/bin`, `/opt/homebrew/bin`을 지원한다. 실행 파일 서명이나 해당 설치 폴더의 동일 사용자 변조를 검증하는 장치는 아니다. 앱의 O CLI와 Claude 가드는 현재 호스트 옆 O 실행 파일을 절대 경로로 사용한다. Claude 훅은 공식 [exec 형식](https://code.claude.com/docs/en/hooks)의 `command`와 `args`를 나눠 셸과 PATH를 거치지 않는다. 개발·미리보기는 기존 준비 스크립트가 해당 위치에 빌드한다.
6. 거울은 GitHub의 대표 소유 공식 저장소 URL 3종만 따른다. Git 환경 설정 주입과 전역/시스템 Git 설정을 제외하고, 저장소의 URL 재작성·외부 명령·필터·include 등 위험한 설정을 거부한다. 대상 브랜치 하나만 가져오고 서브모듈을 따라가지 않는다. 기존 예약 작업은 다음 실행부터 새 바이너리가 설치돼야 이 동작을 얻는다. 설치한 도구나 예약 작업을 이번 작업에서 변경하지 않는다.
7. CI는 PR의 base 커밋에서 정책 바이너리와 라이선스 검사기를 먼저 보존한다. PR 코드를 실행하기 전에 보존한 검사기로 PR 내용을 검사한다. 포크는 코드 실행 job을 건너뛰며 base의 branch-flow가 거부한다. 개인 브랜치와 PR 작성자를 연결한다. 워크플로 변경을 대표가 열어야 하는 기존 규칙 때문에 대표의 PR 작성 예외를 둔다. 아직 계정이 정해지지 않은 개인 브랜치는 대표만 요청할 수 있다. 커밋 작성자나 원격 직접 push 권한까지 인증하는 규칙은 아니다.
8. 개발 API는 변경 요청에서 일치하는 Origin 또는 same-origin 브라우저 헤더를 요구한다. 이를 로컬 프로세스 인증으로 간주하지 않는다. 같은 컴퓨터의 프로세스는 이 헤더를 만들 수 있다.

## 미해결 경계와 후속 조건

- 실행 중인 턴의 결정 파일, 실행 계획·모드 표식, 터미널 입력·출력·완료 파일과 이벤트/DB는 동일 OS 사용자가 직접 바꿀 수 있다. 현재 파일 프로토콜에 nonce·해시만 추가하면 그 파일/검증기를 같은 권한에서 바꿀 수 있어 출처 인증이 되지 않는다. 상태를 소유하는 브로커와 에이전트의 쓰기 권한을 OS에서 분리하고 인증된 IPC로 전달해야 해결된다. 이 변경은 배포·자격 증명 전달·프로바이더 실행까지 함께 설계해야 하며 이번 패치로 완료되지 않았다.
- 승인된 계획/모드의 불변 스냅샷을 러너 시작에 전달하는 API도 별도 후속 작업이다. 현재 dispatch 이후 파일 교체 창이 남아 있다. 유효한 계획인지 재검사하는 것과 사람이 승인한 내용인지 확인하는 것은 다르다.
- 터미널 완료 표식은 문서 전달/중복 방지 표식이다. 과제 파일에도 담기므로 비밀 인증 토큰으로 보지 않는다. 계획 파일의 크기·수정 시각 안정성도 출처 인증이 아니다. 터미널 계획은 작성자를 확인할 수 없다는 안내와 실제 내용을 보여 준 뒤 사람의 실행을 기다린다.
- 원시 진단 로그의 임의 비밀을 완전하게 지울 수 있다고 보장하지 않는다. 실행 간 OS 읽기 격리, Unix 상태 루트 권한, 로그 보관/내보내기 정책은 후속 설계가 필요하다. 무차별 마스킹으로 정상 대화·검토 증거를 훼손하지 않는다.
- PR base 조회 후 retarget 경합, 동일 사용자의 바이너리/상태 변경, 웹뷰 스크립트 장악 뒤의 명령 호출은 남는다. 원격 GitHub 보호 설정은 여기서 읽거나 바꾸지 않았다. 프런트가 보내는 클릭 시각을 사람의 증명으로 추가하지 않는다.

## 검증 및 호환성

실제 상태·계정·모델 호출 없이 임시 폴더와 가짜 CLI로 승인·시작·경로·권한 경계를 시험한다. CLI 옵션은 설치된 공식 도움말에서 확인했다. Codex 프로젝트 설정이 허용된 협업 불리언 외의 내용을 담거나 사용자 지정 Git/gh 설치 위치만 있는 환경은 시작을 거부할 수 있다. 개발 서버의 헤더 없는 변경 클라이언트도 거부된다. 구체적인 실행 결과와 미검증 범위는 조치표에 기록한다.
