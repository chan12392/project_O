# ADR-0019: 전체 탐색, 로컬 이미지, 예약 총괄 요청

상태: 채택 (2026-11-03)

## 결정

- 왼쪽의 검색·대시보드·다음 할 일·자동화는 프로젝트 전체를 대상으로 한다. 오른쪽 에이전트 작업에는 현재 프로젝트의 설계와 대시보드를 둔다.
- 총괄과 작업 기록에 나온 로컬 이미지는 현재 프로젝트 또는 해당 카드의 분리 작업 폴더에 속할 때만 미리 본다. PNG·JPEG·GIF·WebP는 최대 10MB이며 외부 URL은 자동으로 가져오지 않는다. 파일 열기는 사용자의 조작으로만 실행한다.
- 예약은 Windows 작업 스케줄러에 등록한다. 실행 파일과 O가 만든 예약 ID만 스케줄러에 전달하고, 요청 내용은 O 상태 폴더에서 읽는다. 중복 실행을 막고 Windows에 로그인된 동안 앱이 꺼져 있어도 실행한다. PC가 꺼져 있거나 절전 중이면 해당 시간에 실행되지 않는다.
- 예약은 기본적으로 읽기 전용 총괄이 만든 계획을 자동 분배한다. 사용자가 저장한 예약 자체를 분배 승인으로 취급하며, 일반 권한을 유지하고 하루 예산·중복·동시 실행 등 기존 자동 실행 제한과 카드 정책을 통과해야 분배한다. 설계까지만 진행하도록 선택할 수도 있다. 예약 삭제는 이후 실행을 막으며 이미 시작한 총괄은 중지하지 않는다.
- 예약 총괄과 자동 분배에는 Antigravity를 사용하지 않는다. [공식 FAQ](https://antigravity.google/docs/faq)는 소비자 플랜에서 제3자 앱으로 CLI를 감싸는 방식을 지원하지 않는다고 명시한다. 기존 수동 실행 경로는 별도 검토가 필요하다.

## 이유와 한계

화면이 임의 파일이나 웹 이미지를 읽지 않게 하고, 기존 CLI와 정책 경로를 재사용한다. 작업 결과 자동 병합, 다른 사용자로 실행, PC 절전 해제 및 예약 실행의 정확한 정시 보장은 제공하지 않는다.

## 개정 1 (2026-11-09): 예약 실행의 실제 조건

공개 전 점검에서 DESIGN §8의 "사람이 보지 않는 자동 실행은 하지 않는다"와 이 ADR의 예약 자동 분배가 서로 어긋났다. 코드가 하는 일을 기준으로 적는다. DESIGN §8도 같은 내용으로 고쳤다.

- 예약은 사용자가 앱(자동화)이나 `o schedule create`로 만든 것만 돈다. 기본으로 등록된 예약은 없다. Windows 외 OS에서는 예약을 만들 수 없다.
- 예약 총괄은 Claude·Codex만 쓰고 읽기 전용으로 돈다. 승인할 사람이 없어서다. YOLO 예약은 거부하고, Antigravity 예약도 거부한다.
- 앱에서 "자동 분배"는 기본으로 켜져 있다. 켜진 예약은 총괄의 계획을 `o dispatch`와 같은 카드 정책과 YOLO 자동 실행과 같은 한도로 검사한다: 하루 사용 예산이 꺼져 있으면 분배하지 않고, 카드 수·한 시간 횟수·같은 계획 반복(기본 3장·2회·30분), 같은 대화의 진행 중 실행을 확인한다. 카드는 일반 권한(YOLO 아님)으로 실행한다.
- 총괄이 사람에게 질문을 남기면 분배하지 않고 예약의 마지막 결과에 실패로 남긴다.
- 구현: `crates/o-core/src/schedule.rs`, `crates/o-cli/src/commands/schedule.rs`, `crates/o-core/src/lead/mod.rs`의 `send_with_scheduled_autorun`, `crates/o-core/src/run/yolo.rs`의 `check_auto_run`.
- 예약 실행이 각 공급자의 소비자 약관(자동화 접근 조항)에 맞는지는 배포 전에 다시 확인한다.
