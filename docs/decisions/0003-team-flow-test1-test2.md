# ADR-0003: test_2·test_1 두 단계 통합과 대표 병합

- 상태: 승인 (대표 결정)
- 날짜: 2026-11-02
- 승인: [x] A  [ ] B
- 관련: `AGENTS.md` 브랜치·병합 흐름, ADR-0002

## 배경

지금까지는 `test` 하나에 두 사람의 작업을 모으고, `test` → `main`은 두 사람이 모두 승인해야 병합했다. 함께 돌려 보는 자리와 검증을 마친 결과가 한 브랜치에 섞여, 무엇이 확인된 상태인지 구분하기 어려웠다. 승인 대기도 흐름을 막았다.

## 결정

```
개인·작업 브랜치 ──PR──▶ test_2 ──PR──▶ test_1 ──PR──▶ main
```

- `test_2`: 자유 통합. 개인 브랜치와 `<개인>-<주제>` 작업 브랜치에서 누구나 PR을 올리고 누구나 병합한다. 읽기 전용 거울은 `test_2`를 따른다.
- `test_1`: `test_2`에서 문제없이 돌아간 것만, `test_2`에서만 PR을 받는다. 병합은 대표(A, GitHub `chan12392`)와 대표의 에이전트만 한다.
- `main`: `test_1`에서만 PR을 받는다. 병합은 대표(와 대표의 에이전트)만 한다. 두 사람 승인 규칙은 없앤다.
- `test_1`·`test_2`·`main`은 보호 브랜치다. 직접 커밋·push하지 않는다.
- 깨끗한 에이전트 프로필은 보호 대상인 O 상태 폴더 밖 `%LOCALAPPDATA%/project_O-agents/<cli>/home`으로 옮긴다.

## 적용 지점과 한계 (비공개 무료 플랜)

| 지점 | 하는 일 | 한계 |
|---|---|---|
| 에이전트 훅 `o hook` | 보호 브랜치 커밋·push 차단. `gh pr merge`와 `gh api` 병합 호출(`pulls/<n>/merge`, `merges`, GraphQL 병합)은 PR base와 `gh` 로그인을 확인해 `test_1`·`main`이면 대표만 통과. 확인 실패는 차단 | 에이전트 셸 명령만 본다. 사람이 직접 친 명령, `curl` 등 gh 밖의 GitHub API 호출은 보지 못한다 |
| git 훅 `o scan` | 보호 브랜치 커밋, 보호 브랜치로의 push 차단 | `--no-verify`나 훅 미설치 PC에서는 돌지 않는다 |
| CI `branch-flow.yml` | 흐름 밖 PR을 실패로 표시 | 무료 플랜은 필수 검사를 걸 수 없어 병합 버튼을 막지 못한다 |
| CI `merge-guard.yml` | 대표가 아닌 사람이 `test_1`·`main`에 병합·push하면 실패로 알림 | 사후 경보다. 이미 들어간 병합은 대표가 되돌린다 |

GitHub 웹 화면의 병합 버튼은 기술적으로 막을 수 없다. 저장소를 유료 플랜이나 공개로 바꾸면 브랜치 보호(필수 검사, 병합 권한 제한)를 켜서 위 규칙을 서버에서 강제한다.
