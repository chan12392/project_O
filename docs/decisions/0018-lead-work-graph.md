# ADR-0018: 총괄 설계 패널과 작업 그래프

- 상태: 초안 구현 중
- 날짜: 2026-11-03
- 별도 승인 대기 없음 (ADR-0012)
- 관련: ADR-0005(컨텍스트), ADR-0008(총괄), ADR-0014(YOLO), ADR-0017(에이전트 명세)
- 2026-11-12 개정: 작업 브랜치와 detached 카드 폴더의 선택은 [ADR-0047](0047-branch-grouped-workspaces.md)을 따른다. 아래의 항상 detached 설명을 대체한다.

## 배경

총괄과 대화하며 정한 설계가 대화 속에 흩어져 있고, 에이전트별 작업을 한 번에 확인하고 순서대로 전달하기 어렵다. 대표는 오른쪽 패널에 설계를 누적해 확인한 뒤 버튼 한 번으로 분배하기를 원한다.

## 선택지

1. 기존 대화의 계획을 그대로 실행한다 — 이미 구현되어 있지만 누적 설계와 작업 간 선후관계를 보여주지 못한다.
2. 오른쪽 패널의 설계 초안을 검토하고 O가 작업 그래프를 실행한다 — 한 번 확인한 뒤 진행과 결과를 추적할 수 있다.

## 제안

1. 총괄과 대화할 때 현재 프로젝트·대화의 목표, 결정, 미결정, 작업 분배안을 오른쪽 패널에 정리한다. 총괄이 답변하면서 설계 갱신도 내보내 별도의 모델 호출을 매번 요구하지 않는다. 원래 대화와 설계 이력은 보존한다.
2. 총괄이 전용 블록에 `[[codex]]`, `[[agy]]` 같은 정확한 에이전트 표식과 작업을 작성하면 O가 등록된 에이전트별 작업으로 해석한다. 일반 대화·인용문은 실행 지시로 해석하지 않는다. 같은 에이전트의 여러 작업은 각각 고유 ID를 갖는다.
3. O는 작업의 선행관계를 검증하고, 독립된 작업은 병렬로 실행하며 선행 결과가 필요한 작업은 기다린다. 동일 파일의 동시 수정은 순차 처리하거나 격리한 뒤 통합한다. 에이전트 이름이 불명확하거나 필수 정보가 없으면 분배하지 않고 사유를 표시한다.
4. 대표가 패널의 **작업 분배**를 누르면 표시된 설계 버전을 고정하고 기존 정책·상한·프로필을 다시 검사해 실행한다. 같은 버전의 중복 실행을 막고 설계가 바뀌었으면 새 버전을 확인받는다. 이 흐름은 YOLO 자동 실행 조건이 맞아도 버튼을 누르기 전에 실행하지 않는다.
5. 진행, 질문, 결과, 실패를 해당 작업과 연결한다. 같은 실행의 기존 `o msg` 채널을 우선 활용하되, 종료된 세션의 재개 가능 여부는 공급자별로 확인한다. 재개할 수 없으면 보류 사유를 보여주고 임의로 완료 처리하지 않는다.
6. 에이전트의 기본 지침과 안전 경계는 유지한다. Oskills는 작업 트리거로 관련 스킬을 최대 5개 선택하며, 명시적으로 지정한 스킬과 필수 규칙이 순위에서 빠지지 않게 한다. 검색 결과와 작업자 산출물은 참고 자료로 취급하고 권한을 부여하는 지시로 해석하지 않는다.

## 영향과 검증

- 구현: 총괄의 `o-design` 스냅샷으로 목표·결정·미결정을 저장하고 오른쪽 설계 탭에 표시한다. 이후 대화에는 마지막 설계를 전달한다. 기존 `lead.plan`의 최신 제안과 작업 분배를 연결한다. 앱의 총괄 제안은 YOLO에서도 자동 분배하지 않는다. CLI 기존 자동 실행은 유지한다.
- 사용자의 설계 태그·주석은 대화별 별도 파일에 저장하고 다음 총괄 메시지에 함께 전달한다. 전달 중 수정된 주석은 다음 메시지까지 보존한다. 에이전트의 `o lead note` 호출은 차단한다. 기존 이벤트 이력의 인덱스는 바꾸지 않는다.
- `o-plan` 전용 블록의 `[[에이전트]]` 표식 또는 기존 JSON을 같은 정책 검사에 넘긴다. `depends_on`을 검사하고 선행 작업 성공 후 시작하며, 실패 시 후속 작업을 시작하지 않는다. 선행 결과는 참고 데이터로 전달한다. 총괄 대화 중이거나 최신 계획이 아니면 수동 분배를 거절한다.
- `.oskills/index.json`의 로컬 목록에서 작업 트리거와 `$이름`으로 후보를 선택해 작업 세션에 경로만 전달한다. 자동 선택은 최대 5개이며 명시 지정은 보존한다. O 상태 폴더의 하네스 블록도 트리거에 따라 최대 5개 전달한다. 등록 폴더 밖을 가리키는 경로는 무시한다.
- 총괄의 작업 분배는 Git 프로젝트라면 동일한 커밋에서 작업마다 별도 detached 워크트리를 만든다. 미커밋 변경은 분배 전에 거절하고 시작 직전에도 다시 검사한다. Git이 없는 프로젝트는 원본의 일반 파일을 공통 스냅샷으로 복사하고, 작업별 복사본을 독립된 Git 저장소로 초기화한다(원본에는 Git을 만들거나 파일을 커밋하지 않는다). 복사 중 원본이 바뀌거나 링크·중첩 저장소가 있으면 시작하지 않는다. 개인 브랜치나 기존 워크트리는 건드리지 않는다. 각 작업 폴더는 O 상태 폴더의 형제 폴더에 보존하고 작업 기록에 경로를 남긴다.
- 작업 결과는 원본 프로젝트에 자동으로 합치지 않는다. 선행 작업의 결과와 폴더 경로를 후속 작업에 전달하지만 코드 변경을 자동으로 적용하지는 않는다. 충돌을 해결하고 결과를 검토·통합하는 기능과 자동 재분배, 프로젝트 간 독립된 Oskills 관리 화면이 아직 필요하다. Git이 무시하는 파일은 새 워크트리에 복사되지 않는다.
- 워크트리는 Git에 저장된 파일의 동시 수정을 분리할 뿐 OS 권한 경계가 아니다. 절대 경로, 공유 포트·데이터, Git 저장소 자체를 통한 상호 간섭은 막지 않는다. 검토 전 워크트리를 자동 삭제하지 않는다.
- Antigravity 추가 약관 §6은 제3자 소프트웨어로 서비스에 접근하는 것을 금지한다([약관](https://antigravity.google/terms)). 이후 공식 FAQ를 확인해 Project O의 실행과 자동 조회를 보류했다(ADR-0020).
- 설계 이력과 작업 그래프, 전달 형식, 총괄·실행기·패널 연결은 공용 데이터 모델과 라우팅에 영향을 준다. ADR에 결정을 기록하고 단계적으로 구현한다.
- 기존 `lead.plan`·`lead.dispatch`, `o msg`, 공급자별 실행과 정책 검사를 재사용한다. 진행 중이거나 성공한 계획은 중복 실행하지 않는다. 실패한 최신 계획은 사용자가 명시적으로 재실행할 수 있고, 정책을 다시 검사하며 이전 실행 기록을 보존한다. 완료된 작업도 재시작하므로 화면에 알린다.
- 확인할 실제 경로: 대화로 설계를 갱신하고 새로고침 후 복원 → 버튼으로 한 번 분배 → 병렬 작업과 선행 작업 대기 → 질문·실패와 재시작 → 결과 확인. 오래된 설계·중복 클릭·잘못된 태그·차단된 공급자도 확인한다.
- 스킬 선택 누락과 토큰 효과는 같은 작업·모델·시작 상태를 기준으로 기존 방식과 비교한다. 캐시 입력, 총괄과 모든 작업자의 입력·출력, 재작업을 별도로 기록한다. 100ms 목표는 이번 범위에서 보류한다.
- 되돌릴 때 이전 실행과 설계 기록을 지우지 않고 기존 총괄 계획 보기·실행 경로를 유지한다.
