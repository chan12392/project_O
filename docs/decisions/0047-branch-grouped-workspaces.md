# ADR-0047: 브랜치별 실행 표시와 카드 작업 폴더

- 상태: 구현
- 날짜: 2026-11-12
- 관련: [ADR-0018](0018-lead-work-graph.md), [ADR-0037](0037-parallel-cards-and-subagents.md), ADR-0045

## 결정

프로젝트의 실행 목록은 브랜치별로 묶는다. 실행은 `run.branch` 이벤트(`at`, `branch`)에 실행 당시의 브랜치를 기록하고 Rust/TS `RunView.branch`로 읽는다. 현재 체크아웃으로 과거 기록을 추정하지 않는다. 기록이 없는 실행은 ‘브랜치 정보 없음’으로 보이며 원본 이벤트는 바꾸지 않는다. 후속 실행은 원래 실행에 기록된 브랜치를 유지한다.

개인 브랜치(`younchan`, `yongwoo`, `eunmi`, `yeeun`) 또는 일반 저장소의 기본 브랜치(`main`, `master`, `develop`)에서 분배하면 실행 하나에 작업 브랜치를 하나 만든다. 이름은 `<개인>-o-<제목의 영문·숫자 요약>-<실행 ID>`이며 일반 저장소는 개인 접두를 생략한다. 제목에 영문·숫자가 없으면 `task`를 쓴다. 첫 카드가 이 브랜치를 사용하고 다른 카드는 동일 기준 커밋의 detached 워크트리를 사용한다. 이미 작업 브랜치에서 실행했다면 브랜치를 더 만들지 않고 모든 카드를 별도 워크트리로 격리한다. 원본 체크아웃의 브랜치·파일은 바꾸지 않는다.

개인별 작업 브랜치 3개 상한을 적용한다. 같은 저장소를 쓰는 O 실행들은 Git 공통 폴더의 파일 잠금으로 브랜치 수 확인과 생성을 직렬화한다. 상한에 걸리면 기존 작업 브랜치 사용 또는 완료한 브랜치 정리를 안내하며 임의 삭제·강제 이동하지 않는다. 원래 보호 브랜치 분배 차단은 유지한다. 워크트리 생성 전후 기준 커밋·원본 브랜치·미커밋 변경 검사를 유지하고 실패 시 생성한 자료를 보존한다.

Git이 없는 폴더는 기존 독립 복사본 방식을 유지한다. detached 원본은 브랜치 이름을 지어내지 않는다. 카드 작업 폴더와 원본의 변경 분리, 선행 변경 인계, 검토용 원본 보존은 기존 계약을 따른다.

## Orca 표시와 보존

Orca의 외부 워크트리 자동 표시는 프로젝트별 `external-worktree-visibility` 설정으로 제어한다. 내부 카드 폴더를 숨겨도 작업 폴더·Git 등록·결과 기록은 보존된다. O가 다른 제품의 설정 파일을 직접 고치거나 워크트리를 자동 삭제하지 않는다. 이번 사용자의 Orca 정리는 공식 CLI로 해당 프로젝트의 외부 워크트리 표시만 숨긴다.

## 검증

Git 임시 저장소에서 작업 브랜치 하나 생성, 카드 간·원본 변경 격리, 기존 작업 브랜치의 반복 실행, 3개 상한에서의 원본·등록 보존을 검사한다. 이벤트 접기 및 사이드바 정렬·선택·접기는 별도 Rust/TS 회귀 검사와 화면 검증으로 확인한다.

## 이전 문서와의 차이

ADR-0018의 ‘항상 detached 워크트리’ 설명은 이번 결정으로 대체한다. 작업 결과를 원본 프로젝트에 자동으로 합치지 않고 검토할 수 있게 보존한다는 원칙은 그대로다.
