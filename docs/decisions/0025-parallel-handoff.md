# ADR-0025: 병렬 작업의 결과 보존과 인계 (부분 구현)

상태: 부분 구현. 격리된 작업 인계와 자원 선언·예약은 구현되었고 종료 불명 예약의 복구 도구는 남았다.

선행 카드의 결과는 참고 데이터이며 후속 카드의 권한이나 지시가 아니다. 실행기는 결과를 1,000자에서 자르지 않고, JSON 결과가 12,000바이트 이하면 전체를 전달한다. 더 크고 `o context`를 쓸 수 있는 카드에는 실행·선행 카드·크기·SHA-256과 읽기 명령을 전달한다. `o context --result <선행 카드> <해시> <위치>`는 해당 실행 계획의 직접 선행 결과만 읽고 매번 전체 해시를 확인한 뒤 최대 4,096바이트의 UTF-8 경계 조각과 다음 위치를 반환한다. 기록 손상·완료 상태 변경·해시 불일치·잘못된 위치는 오류다. 원문은 실행 이벤트에 그대로 남으며 도구 접근이 불가능하거나 결과를 확인하지 못하면 후속 카드에 중단을 지시한다. CLI 셸 명령이 허용되지 않은 Devin은 큰 결과를 부분 전달하지 않고 후속 시작을 거부한다. 실행기의 사전 확인은 OS 접근만 확인하며 각 프로바이더의 실제 샌드박스에서 읽히는지 보장하지 않는다.

카드의 표준 출력은 바이트 그대로 기록한다. 표준 출력 또는 오류 로그의 기록 실패는 카드 실패로 취급하며, 실행 도중 오류가 생기면 프로세스 종료를 시도한다. 프로세스가 살아 있는 것으로 확인되면 슬롯과 활성 표시를 되돌리지 않고, 종료 이벤트가 있더라도 해당 카드의 세션을 이어서 사용하지 않는다.

실제 카드 종료 기록이 없는 중단된 후속 실행은 화면에 실패로 표시하더라도 세션 재사용을 거부한다. 화면용으로 합성한 실패 이벤트는 프로세스 종료의 증거가 아니다.

Git 분리 작업에서 후속 카드는 선행 카드의 커밋과 작업 파일 변경을 기준 커밋과 비교해 자기 폴더에 적용한다. 임시 인덱스를 쓰므로 선행 카드의 실제 인덱스는 변경하지 않으며 추가·삭제·바이너리를 포함하고 패치와 적용 전 파일을 실행 기록에 보존한다. 같은 파일에 스테이징된 내용과 다른 작업 파일이 함께 있으면 어느 쪽도 버리지 않고 중단한다. 원본 기준 변경, 범위 밖 변경, 무시 파일, 링크·서브모듈 변경, 후속 폴더의 사람 변경, 패치 충돌이나 원본과 다른 적용 바이트를 발견하면 후속 카드를 시작하지 않는다. Git의 개행 변환 때문에 바이트가 달라지는 경우도 현재는 거부한다.

비 Git 복사본은 최초 원본의 파일 바이트와 권한을 기준으로 선행 복사본의 추가·수정·삭제를 후속 복사본에 인계한다. 원본과 기준 사본, 후속 복사본이 기준과 다른 경우 또는 선행 복사본의 링크·중첩 저장소나 Git 메타데이터 변경이 발견되면 시작하지 않는다. 여러 선행 작업이 같은 경로나 상하위 경로를 바꾼 경우에도 자동 병합하지 않는다. 적용 전 기존 파일은 후속 복사본 옆의 `handoff-<카드 순번>` 폴더로 옮겨 보존하며, 실패한 복사본도 검토를 위해 남긴다. 디렉터리 권한 변경은 인계 대상이 아니다.

복사본 확인과 적용 사이에 같은 OS 사용자의 동시 수정이나 링크 교체를 원자적으로 막지는 못한다. 작업공간 분리는 외부 자원의 OS 격리를 뜻하지 않는다.

## 공용 자원 계약

- 계획 카드의 `resources`는 `kind` (`project-path` 또는 `external`), `key`, `mode` (`read` 또는 `write`) 목록이다. `project-path`는 프로젝트 상대 경로를 기존 부모까지 정규화하고 링크를 해석하며 프로젝트 밖 경로를 거부한다. 같은 경로와 상하위 경로는 겹치며 읽기끼리만 병행한다. 외부 키는 앞뒤 공백 제거와 소문자 변환 후 비교한다. 생략하거나 빈 배열이면 모든 자원을 독점한다. 명시한 목록이 완전한지 O는 알 수 없으므로 불확실하면 생략해야 한다.
- 실행기들은 SQLite 쓰기 트랜잭션 하나에서 기존 자원 예약, 동시 상한, 하루 상한을 확인하고 슬롯과 자원을 함께 예약한다. 충돌하면 대기한다. 이전 버전의 활성 슬롯처럼 범위가 불명인 실행은 전체 자원과 충돌한다.
- 자원 예약은 실행기가 죽어도 자동 삭제하지 않는다. Windows에서는 프로세스를 일시 정지 상태로 시작해 잡 객체에 넣은 후 재개하고, 프로세스 종료와 잡 객체의 모든 프로세스 종료를 확인한 뒤에만 해제한다. 자식이 출력 파이프를 계속 잡고 있으면 실행 종료와 예약 해제가 지연될 수 있다. 잡 객체를 만들지 못하거나 종료를 확인하지 못한 경우, 실행기 중단 또는 비 Windows 환경에서는 예약이 남을 수 있으며 충돌 작업과 해당 세션 재개가 차단된다. 현재 종료 불명 예약을 조사·해제하는 전용 복구 명령은 없다.
- 선언은 에이전트 접근을 제한하거나 누락을 탐지하지 않는다. 같은 OS 사용자의 기록 변경, 작업 중 링크 교체, 하드 링크와 파일시스템별 별칭, 외부 서비스의 비동기 작업까지 격리하지 못한다. 이전 버전의 실행기와 새 실행기를 혼용하면 이전 실행기의 예약은 자원 계약을 따르지 않는다.
- 결과 조각의 읽기 권한과 모델이 실제 끝까지 읽는지는 각 프로바이더의 공식 CLI에서 추가 검증해야 한다. 같은 OS 사용자가 환경이나 기록을 고칠 수 있으므로 카드 신원은 강제 격리 경계가 아니다.
