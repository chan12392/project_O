# ADR-0025: 병렬 작업의 결과 보존과 인계 (부분 구현)

상태: 진행 중. 격리된 Git·비 Git 작업의 선행 변경 인계는 구현되었으며 자원 선언과 실행 간 충돌 관리는 남았다.

일반 `o dispatch`도 총괄 분배와 같이 실행 전에 프로젝트를 검사하고 카드마다 별도 작업 폴더를 만든다. Git 프로젝트의 미커밋 변경은 보존하며 분배를 거부한다. 결과는 각 카드의 작업 폴더에 남고 원본에 자동 적용하지 않는다. CLI 응답의 `isolated`와 `o status <runId>`의 `작업 폴더`에서 분리 여부와 위치를 확인한다.

새로 분리한 실행의 `o status`는 작업 전 Git 커밋 또는 비 Git 기준 복사본 경로도 표시한다. 비 Git 기준은 생성 시 파일 내용·파일 권한·경로의 해시를 저장하고 조회 시 비교한다. 기록 자체를 바꾸는 같은 사용자에 대한 보안 보증은 아니다. 해시가 없는 예전 실행은 직접 비교해야 한다. 원본에 안전하게 변경을 적용하는 기능은 아직 없다.

`o changes <runId> <cardId>`는 해당 카드의 읽기 전용 변경 목록을 JSON으로 보여 준다. Git은 기준 대비 변경과 스테이징·작업 파일·미추적·무시 파일을 나눠 표시하고, 변경이 숨겨질 수 있는 assume-unchanged·skip-worktree 파일은 `masked`에 별도 표시한다. 이 파일의 실제 변경 여부는 따로 확인해야 한다. 비 Git은 기준 복사본과 파일 내용·권한을 비교하며 기준 해시가 없거나 불일치하면 비교를 거부한다. 실행 중에도 조회할 수 있으므로 목록은 그 시점의 참고 정보이며, 안전한 원본 적용을 보증하지 않는다. 카드에서는 다른 실행의 파일 목록 접근을 막는다.

선행 카드의 결과는 참고 데이터이며 후속 카드의 권한이나 지시가 아니다. 실행기는 결과를 1,000자에서 자르지 않고, JSON 결과가 12,000바이트 이하면 전체를 전달한다. 더 크고 `o context`를 쓸 수 있는 카드에는 실행·선행 카드·크기·SHA-256과 읽기 명령을 전달한다. `o context --result <선행 카드> <해시> <위치>`는 해당 실행 계획의 직접 선행 결과만 읽고 매번 전체 해시를 확인한 뒤 최대 4,096바이트의 UTF-8 경계 조각과 다음 위치를 반환한다. 기록 손상·완료 상태 변경·해시 불일치·잘못된 위치는 오류다. 원문은 실행 이벤트에 그대로 남으며 도구 접근이 불가능하거나 결과를 확인하지 못하면 후속 카드에 중단을 지시한다. CLI 셸 명령이 허용되지 않은 Devin은 큰 결과를 부분 전달하지 않고 후속 시작을 거부한다. 실행기의 사전 확인은 OS 접근만 확인하며 각 프로바이더의 실제 샌드박스에서 읽히는지 보장하지 않는다.

카드의 표준 출력은 바이트 그대로 기록한다. 표준 출력 또는 오류 로그의 기록 실패는 카드 실패로 취급하며, 실행 도중 오류가 생기면 프로세스 종료를 시도한다. 프로세스가 살아 있는 것으로 확인되면 슬롯과 활성 표시를 되돌리지 않고, 종료 이벤트가 있더라도 해당 카드의 세션을 이어서 사용하지 않는다.

Git 분리 작업에서 후속 카드는 선행 카드의 커밋과 작업 파일 변경을 기준 커밋과 비교해 자기 폴더에 적용한다. 임시 인덱스를 쓰므로 선행 카드의 실제 인덱스는 변경하지 않으며 추가·삭제·바이너리를 포함하고 패치와 적용 전 파일을 실행 기록에 보존한다. 같은 파일에 스테이징된 내용과 다른 작업 파일이 함께 있으면 어느 쪽도 버리지 않고 중단한다. 원본 기준 변경, 범위 밖 변경, 무시 파일, 링크·서브모듈 변경, 후속 폴더의 사람 변경, 패치 충돌이나 원본과 다른 적용 바이트를 발견하면 후속 카드를 시작하지 않는다. Git의 개행 변환 때문에 바이트가 달라지는 경우도 현재는 거부한다.

비 Git 복사본은 최초 원본의 파일 바이트와 권한을 기준으로 선행 복사본의 추가·수정·삭제를 후속 복사본에 인계한다. 원본과 기준 사본, 후속 복사본이 기준과 다른 경우 또는 선행 복사본의 링크·중첩 저장소나 Git 메타데이터 변경이 발견되면 시작하지 않는다. 여러 선행 작업이 같은 경로나 상하위 경로를 바꾼 경우에도 자동 병합하지 않는다. 적용 전 기존 파일은 후속 복사본 옆의 `handoff-<카드 순번>` 폴더로 옮겨 보존하며, 실패한 복사본도 검토를 위해 남긴다. 디렉터리 권한 변경은 인계 대상이 아니다.

Windows와 Unix의 비 Git 복사와 비교는 일반 파일 핸들의 하드 링크 수를 확인하고 링크 수가 1이 아니면 거부한다. Windows에서는 파일을 읽는 동안 쓰기·삭제 공유를 허용하지 않는다. 이 검사는 작업 폴더의 상위 디렉터리를 동시에 교체하는 모든 경합을 차단하지 않는다.

복사본 확인과 적용 사이에 같은 OS 사용자의 동시 수정이나 링크 교체를 원자적으로 막지는 못한다. 동일 파일·외부 자원에 대한 사전 범위 선언과 실행 간 충돌 관리, 종료가 불확실한 프로세스의 완전한 복구는 아직 필요하다. 작업공간 분리는 외부 자원의 OS 격리를 뜻하지 않는다.

## 필요한 공용 계약 (제안, 미구현)

- 계획 카드의 `resources`는 `kind` (`project-path` 또는 `external`), `key`, `mode` (`read` 또는 `write`) 목록으로 검토한다. 경로는 프로젝트 기준으로 정규화하고 링크를 해석한 뒤 프로젝트 밖이면 거부하며, 같은 자원의 쓰기는 실행 간에도 순차화한다. 선언이 없거나 검증할 수 없으면 독점 실행 또는 안전 중단이 필요하다. 선언만으로 실제 외부 접근을 OS가 격리하거나 에이전트가 빠뜨린 자원을 탐지할 수는 없다.
- 결과 조각의 읽기 권한과 모델이 실제 끝까지 읽는지는 각 프로바이더의 공식 CLI에서 추가 검증해야 한다. 같은 OS 사용자가 환경이나 기록을 고칠 수 있으므로 카드 신원은 강제 격리 경계가 아니다.
- 실행 임대는 프로세스 종료 확인 전까지 보유하고, 종료 여부를 확인할 수 없으면 같은 자원을 재사용하지 않는다. 같은 OS 사용자 권한의 에이전트가 ID나 파일을 바꿀 수 있으므로 환경변수만으로 호출자 인증을 보장하지 않는다.
