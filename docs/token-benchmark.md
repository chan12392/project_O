# 토큰 비교: 기본 하네스 vs 깨끗한 에이전트 + 세션 공유

같은 일을 두 방식으로 시켜 카드당 토큰을 비교한다(ADR-0005).

| 묶음 | 실행 방법 | 카드가 받는 컨텍스트 |
|---|---|---|
| A. 기본 하네스 | `o dispatch --profile own --no-context plan.json` | 각 CLI가 평소 읽는 사용자 하네스(전역 AGENTS·USER·MEMORY, 훅, 스킬, MCP) + 작업카드 |
| B. 깨끗한 + 세션 공유 | `o dispatch --profile project-o plan.json` (기본, `--clean`과 같음) | 작업카드 + 그 일과 관련된 이전 작업 조각(최대 1,500자). 더 필요하면 카드가 `o context`로 찾는다 |

`--profile own`만 준 실행과 `--profile project-o --no-context` 실행도 기록되지만 `--compare`에서는 빠진다(`o tokens`의 모드별 표에는 나온다).

## 준비

1. `o agents doctor`가 깨끗함으로 끝나는지 확인한다(B의 전제). 로그인이 안 됐으면 `o agents login <claude|codex>`.
2. 테스트 프로젝트는 홈 폴더 밖, git 저장소로 둔다. 시작 커밋을 기록한다.
3. 비교할 `plan.json` 하나를 정한다. 카드의 `provider`·`model`·`effort`를 고정한다(빈 칸이면 CLI 기본 모델이 바뀌어 비교가 흔들린다).
4. 세션 공유가 효과를 내려면 그 프로젝트에 이전 실행 기록이 있어야 한다. 실제 쓰는 프로젝트에서 재거나, 먼저 관련 작업 몇 개를 돌려 둔다. `o context "<카드 task의 핵심어>" --project <폴더>`로 무엇이 주입될지 미리 볼 수 있다.

## 순서 (공정하게)

B를 먼저 돌린다. A를 먼저 돌리면 A 카드의 결과가 컨텍스트에 쌓여 B에 주입되므로, B가 "답을 보고" 일하게 된다. A는 `--no-context`라 B의 결과를 받지 않는다. 두 실행 모두 하루 사용 예산이 effort를 낮추면 비교가 흔들리므로, 잴 때는 `o budget --off`로 끄고 끝나면 `o budget --on`으로 되돌린다.

```sh
# 0. 비교 시작 시각을 적어 둔다 (예: 2026-11-02T09:00:00Z)
o dispatch --profile project-o C:/bench/plan.json   # B
o status <runId>                               # 모든 카드가 끝날 때까지
git -C C:/bench/project restore . ; git -C C:/bench/project clean -fd   # 프로젝트를 시작 커밋으로 (사람이 확인 후)
o dispatch --profile own --no-context C:/bench/plan.json   # A
o status <runId>
o tokens --compare --project C:/bench/project --since 2026-11-02T09:00:00Z
```

- 한 번으로는 흔들림이 크다. 같은 순서로 3번 이상 반복하고 `--since`로 그 구간만 본다.
- 프로바이더의 프롬프트 캐시 때문에 뒤에 돈 쪽의 `캐시 입력`이 유리할 수 있다. 반복할 때 사이에 시간을 두거나, 순서를 바꾼 회차도 한 번 넣고(이때는 B 전에 A의 실행 폴더를 치워 두거나 다른 프로젝트 복사본에서) 결과를 함께 본다.
- 같은 PC에서 그 구간에 다른 실행을 돌리지 않는다. 섞이면 `--project`로 걸러진다.
- 카드가 실패하거나 사람이 개입한 회차는 빼고 다시 돈다. 결과 품질(테스트 통과, 바꾼 파일)도 같이 확인한다 — 토큰이 적어도 일을 못 했으면 의미가 없다.

## 보고서 읽기

```text
                        기본 하네스         깨끗+세션 공유       차이
실행                              3                  3          -
카드                              9                  9          -
카드당 새 입력               18,400              6,900       -63%
카드당 캐시 입력             41,200             12,800       -69%
카드당 출력                   3,100              2,700       -13%
카드당 합계                  62,700             22,400       -64%
codex 카드당 합계            62,700             22,400       -64%
```

(숫자는 예시다.)

- **새 입력**: 캐시되지 않은 입력(Claude는 캐시 쓰기 포함). 하네스 크기가 가장 크게 드러나는 줄이다.
- **캐시 입력**: 캐시에서 읽은 입력. 값이 싸지만 한도·컨텍스트 창은 차지한다.
- **출력**: 생각·답변 토큰(Antigravity는 thinking 포함).
- **합계** = 세 값의 합. 카드 수가 다를 수 있어 카드당 평균으로 비교한다.
- 차이 = (B − A) / A. 음수면 B가 적게 쓴 것이다.
- 토큰을 보고하지 않은 카드(시작 전에 실패 등)는 평균에서 빠진다.

다른 보기:

- `o tokens` — 모드별 카드당 평균(프로바이더별 포함)과 실행별·카드별 숫자. `+컨텍스트`는 그 카드에 컨텍스트가 주입됐다는 뜻(`run.context` 이벤트).
- `o tokens --json` — `groups`(모드별), `compare.baseline`/`compare.shared`, `runs`(실행·카드별). 앱 대시보드의 "토큰" 카드도 같은 데이터다.
- 묶음은 실행 폴더의 `clean` 표식(`--profile project-o`)과 카드별 주입 여부로 정한다. 이 기능 이전의 실행은 모두 "주입 없음"으로 잡힌다.
